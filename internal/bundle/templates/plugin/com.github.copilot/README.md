# boxer plugin for GitHub Copilot CLI

Generated by `boxer package copilot` [[.Version]]. Do not edit; regenerate.

## Install

```sh
boxer install copilot --user
```

Copilot CLI's hooks live at user scope, `${COPILOT_HOME:-~/.copilot}/hooks/boxer.json`: repository
hooks under `.github/hooks/` load only from a trusted working directory, which `-p` mode does not
grant unless `COPILOT_ALLOW_ALL` is exactly `true`. The same install writes the skill to
`~/.copilot/skills/boxer/SKILL.md` and the run tool into `~/.copilot/mcp-config.json`.

`boxer` must be on `PATH`; the hook calls it by name.

## What the bundle does

| Component | File | Purpose |
| --- | --- | --- |
| Instruction | `skills/boxer/SKILL.md` | Tells the agent how execution works here |
| Intercept hook | `preToolUse` on `bash` and `powershell` | Mode `rewrite`: `modifiedArgs` replaces the tool arguments. Mode `tool`: deny with the exact fix |
| Run tool | `mcp.json` | `boxer_run`, `boxer_status` |

The mode, the intercept list and the rest of the resolved configuration come from the checkout at
run time: `boxer brief`. Nothing in this package is rendered from anyone's configuration.

## Two hazards

- A hook that **times out fails open** (the tool call proceeds unhooked) while a **non-zero exit
  fails closed**. boxer's hook does no work beyond resolving the scope and always exits 0, and the
  30-second timeout is there for the first provision only.
- **Auto-update is on by default.** Pin `COPILOT_AUTO_UPDATE=false` (or `--no-auto-update`) where
  the version under test matters; a CI environment disables it already.

There are no session-lifecycle rows: the brief reaches the model through the skill and the MCP
server, not through a session-start hook.
