# boxer for Kimi Code CLI

Generated by `boxer package kimi` [[.Version]]. Do not edit; regenerate.

## Status

Kimi Code CLI hooks are `[[ "[[hooks]]" ]]` tables in `~/.kimi-code/config.toml` (user level only), speak
the converged protocol on stdin, and can only allow or block (`permissionDecision`, exit 2).
`updatedInput` is ignored, so the hook cannot rewrite a command. **Use tool mode with Kimi**:

```toml
[harness.kimi]
mode = "tool"
```

The hook then denies shell use with the exact `boxer run` line, and the `boxer_run` MCP tool is the
way in. Both paths are covered by `boxer-eval` (tier t1) against the real Kimi binary.

PATH shims also work: with `boxer shim install` on the `PATH` Kimi starts with, a bare `uname` in
Kimi's `Bash` tool runs in the sandbox (matrix cells `kimi/shims` and `kimi/bash-shim`, 0.43.1,
2026-09-25 and 2026-09-28). An earlier note that Kimi's shell ignores a prepended `PATH` was wrong.
Shims only cover the programs on the intercept list, so tool mode stays the recommended setup.

## Install

1. Append `ai.moonshot.kimi-code/hooks.toml` to `~/.kimi-code/config.toml` (or `$KIMI_CODE_HOME/config.toml`).
2. Merge `ai.moonshot.kimi-code/mcp.json` into `.kimi-code/mcp.json` in the repository.
3. Copy `skills/boxer/` to `.agents/skills/boxer/` in the repository.
4. Run `boxer shim install` and prepend the printed directory to `PATH`.

`boxer install kimi` does steps 2 and 3 and prints the `hooks.toml` block for step 1, since Kimi
hooks live only in the user config.

`boxer` must be on `PATH`. Hooks and shims call it by name.
