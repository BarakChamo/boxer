# boxer plugin for Codex CLI

Generated by `boxer package codex` dev. Do not edit; regenerate.

## Install

Codex installs plugins from marketplaces only; the package carries a local marketplace wrapper:

```sh
codex plugin marketplace add ./boxer     # or ./codex (this view)
codex plugin add boxer@boxer
```

Or write the files into the repository:

```sh
boxer install codex
```

That copies `com.openai.codex/hooks/hooks.json` to `.codex/hooks.json` and the skill to
`.agents/skills/boxer/`. In a linked worktree it also writes the hooks to the main repository's
`.codex/hooks.json`, because Codex reads project hooks from there. Codex runs project hooks only
after you trust them: run `/hooks` once, or pass `--dangerously-bypass-hook-trust` to `codex exec`.

Add the run tool to `.codex/config.toml`:

```toml
[mcp_servers.boxer]
command = "boxer"
args = ["mcp", "--harness", "codex"]
```

`boxer install codex --user` writes the hooks into `~/.codex/config.toml` instead, where they need
no project trust.

`boxer` must be on `PATH`. Hooks call it by name.

## What the bundle does

| Component | File | Purpose |
| --- | --- | --- |
| Instruction | `skills/boxer/SKILL.md` | Tells the agent how execution works here |
| Lifecycle hooks | `com.openai.codex/hooks/hooks.json` | `SessionStart`/`SubagentStart` provision and instruct; `SessionEnd`/`SubagentStop` reclaim per `destroy_on` |
| Intercept hook | `PreToolUse` on `Bash` | Mode `rewrite`: `permissionDecision: allow` + `updatedInput.command`. Mode `tool`: deny with the exact fix |
| Run tool | `mcp.json` | `boxer_run`, `boxer_status` |
| Gap closer | hook rewrite; PATH shims via `boxer shim install` | Codex exposes no per-agent tool restriction boxer could verify, so the rewrite hook is the closure |

The mode in force is a property of the checkout, not of this package: run `boxer brief` to see it.
