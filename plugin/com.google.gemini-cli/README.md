# boxer extension for Gemini CLI

Generated by `boxer package gemini-cli` dev. Do not edit; regenerate.

## Install

```sh
gemini extensions install ./gemini-cli   # this view: hooks are at hooks/hooks.json, where Gemini reads them
```

Or write the files into the repository:

```sh
boxer install gemini-cli
```

That merges the hooks and the run tool into `.gemini/settings.json`, adds `run_shell_command` to
`tools.exclude` there in `tool` mode, and appends the instruction to `GEMINI.md`.

`boxer` must be on `PATH`. Hooks call it by name.

## What the bundle does

| Component | File | Purpose |
| --- | --- | --- |
| Instruction | `AGENTS.md` (`contextFileName`) | Loaded as context for every session |
| Lifecycle hooks | `com.google.gemini-cli/hooks/hooks.json`, copied to `hooks/hooks.json` in this view (Gemini reads only that fixed path; the full package keeps it in the namespace because another client auto-loads `hooks/hooks.json` and rejects the `BeforeTool` key) | `SessionStart` provisions and injects `additionalContext`; `SessionEnd` reclaims per `destroy_on` |
| Intercept hook | `BeforeTool` on `run_shell_command` | Mode `rewrite`: `hookSpecificOutput.tool_input.command`. Mode `tool`: top-level `decision: deny` |
| Run tool | `mcpServers.boxer` | `boxer_run`, `boxer_status` |
| Gap closer | `tools.exclude: ["run_shell_command"]`, written into `.gemini/settings.json` by `boxer install gemini-cli` in `tool` mode | Removes the shell tool entirely in `tool` mode; the agent never forms the intent |

The mode in force is a property of the checkout, not of this package: run `boxer brief` to see it.
