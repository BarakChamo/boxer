## Where boxer reads it

Lowest priority first:

1. `.devcontainer/devcontainer.json`, else `.devcontainer.json` ([mapping](#devcontainerjson))
2. `$XDG_CONFIG_HOME/boxer/boxer.toml`, else `~/.config/boxer/boxer.toml`
3. `boxer.toml` at the repository root
4. `boxer.toml` at the worktree root
5. [`BOXER_*` environment variables](#environment-variables)

`boxer doctor` prints every resolved value and the file or variable it came from.

An unknown key is an error, so a typo cannot silently weaken enforcement. An unknown top-level
*table* is a warning, so a repository written for a newer boxer still loads in an older one.

The code blocks below show defaults unless a comment says `example`.

## Scope

```toml
isolation               = "worktree"   # repo | worktree | session | subagent
on_missing_id           = "degrade"    # degrade | fail
require_worktree        = "warn"       # off | warn | require
require_linked_worktree = false

[worktree]
manage = "off"                         # off | detect
```

| Key | Meaning |
| --- | --- |
| `isolation` | What a sandbox is keyed to. `worktree`: one per git worktree. `repo`: one for all worktrees. `session` / `subagent`: one per agent session or subagent id, for harnesses that supply one |
| `on_missing_id` | When `session`/`subagent` isolation gets no id: `degrade` falls back to the worktree, `fail` refuses |
| `require_worktree` | `warn` runs in a plain repository with a warning. `require` refuses with cause `WORKTREE_REQUIRED`. `off` says nothing |
| `require_linked_worktree` | `true` refuses the main checkout; only a worktree made by `git worktree add` is accepted |
| `worktree.manage` | `detect`: a session in the main checkout shares the repository's sandbox, with a warning, until it moves into a linked worktree |

See [scopes and packs](/docs/concepts/scopes-and-packs).

## Integration

```toml
integration            = "outside"   # outside | inside
mode                   = "rewrite"   # rewrite | tool | off
enforcement            = "both"      # hook | shim | both | audit
on_sandbox_unavailable = "fail"      # fail | passthrough
```

| Key | Meaning |
| --- | --- |
| `integration` | `outside`: the harness runs on the host and its commands run in the sandbox. `inside`: the harness itself runs in the guest ([guide](/docs/guides/inside)) |
| `mode` | `rewrite`: intercepted commands become `boxer run` transparently. `tool`: the shell is denied and `boxer_run` is the way through. `off`: installed but inert |
| `enforcement` | Which mechanisms are live. `both`: hooks where the harness has them, shims elsewhere. `audit`: record what would happen, block nothing ([guide](/docs/guides/enforcement)) |
| `on_sandbox_unavailable` | When the sandbox cannot be provisioned. `fail` refuses the command. `passthrough` runs it on the host, unsandboxed |

## What gets sandboxed

```toml
intercept   = ["npm", "npx", "pnpm", "yarn", "bun", "bunx", "node", "deno",
               "python", "python3", "pip", "uv", "pytest", "cargo", "rustc",
               "go", "make", "cmake"]
passthrough = ["git", "gh", "ssh", "boxer", "smolvm"]
```

| Key | Meaning |
| --- | --- |
| `intercept` | Programs whose commands run in the sandbox |
| `passthrough` | Programs that always run on the host. `git`, `gh` and `ssh` need your credentials and the real repository |

Neither list can be set from the environment.

<Callout type="warn">
Under `enforcement = "shim"` every `intercept` entry becomes a file on `PATH`. A `node` or `python`
shim shadows the interpreter of a harness written in that language, and the harness fails at
startup. Narrow the list to build tools first, for example
`intercept = ["npm", "npx", "pnpm", "yarn", "bun", "make", "cargo", "go"]`.
</Callout>

## Backend

```toml
backend = "smolvm"        # smolvm | container | docker | podman
```

`smolvm` and Apple `container` (macOS 26, Apple Silicon) give each sandbox its own kernel. `docker`
and `podman` give a container that shares the host kernel with every other sandbox. See
[backends](/docs/concepts/backends).

Capabilities, generated from the backends (`go test ./internal/vm -run CapabilityMatrix`):

| backend | boundary | worktree mount | egress allowlist | secrets off argv | proves ownership | env cache | fork | egress log |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `smolvm` | kernel | yes | yes | yes | yes | yes | yes | yes |
| `container` | kernel | yes | — | yes | yes | — | — | — |
| `docker` | namespace | yes | — | yes | yes | — | — | — |
| `podman` | namespace | yes | — | yes | yes | — | — | — |

A backend without a capability refuses the setting that needs it, naming the backend that has it.
In particular, `network.mode = "allowlist"` (the default) is refused on every backend except
`smolvm`; set `network.mode` explicitly to use another. `boxer doctor` prints this table.

## Guest

```toml
image     = ""            # OCI ref, ./archive.tar, a rootfs directory, or "-" for stdin
smolfile  = ""            # a smolvm Smolfile, used instead of image
cpus      = 4
memory    = "4G"          # 4G, 4096M, or 4096 (MiB)
mount_at  = "/workspace"
mounts    = []            # example: ["~/.npm:/root/.npm"], host:guest[:ro]
user      = ""            # name or uid[:gid]
```

| Key | Meaning |
| --- | --- |
| `image` | The guest image. A path starting `./`, `../`, `/` or `~/`, or `-`, is local and not pulled. Empty: inferred from the lockfile (below) |
| `smolfile` | A smolvm Smolfile. Takes precedence over `image` |
| `cpus`, `memory` | Guest allocation |
| `mount_at` | Where the worktree is mounted in the guest. `boxer run` from a subdirectory runs in the matching subdirectory. `integration = "inside"` always mounts at the worktree's host path |
| `mounts` | Extra host directories. The worktree is always mounted |
| `user` | Guest user for `setup`, `start` and every command. Empty: the image's `USER`. `image_setup` always runs as root |

Inferred images, by first lockfile found:

| Lockfile | Image |
| --- | --- |
| `bun.lock`, `bun.lockb` | `oven/bun:1-slim` |
| `pnpm-lock.yaml`, `package-lock.json`, `yarn.lock` | `node:24-bookworm-slim` |
| `uv.lock`, `requirements.txt`, `pyproject.toml` | `python:3.12-slim-bookworm` |
| `Cargo.lock` | `rust:1-slim-bookworm` |
| `go.sum`, `go.mod` | `golang:1-alpine` |
| none | `debian:bookworm-slim` |

With `integration = "inside"` and no image, the default is `mirror.gcr.io/library/node:24-bookworm-slim`.

Inferred images are slim because image size is start-up time (`node:24-bookworm` 8.2s against
`node:24-bookworm-slim`'s 1.9s on an M4). A dependency that compiles from source needs a toolchain
added in `image_setup`.

When `user` cannot write the worktree, boxer fixes it at start: on smolvm the user is given your
host uid; on rootless podman on Linux the sandbox is recreated once with `--userns=keep-id`. Files
it writes are owned by you on the host.

## Preparing the worktree before the sandbox starts

```toml
[prep]
commands = []             # example: ["npm ci $BOXER_TARGET_FLAGS"]
target   = "auto"         # auto | none | os/cpu/libc, e.g. "linux/arm64/musl"

[cache]
enabled  = true
managers = ["auto"]       # or any of npm, pnpm, yarn, bun, uv, poetry, cargo, go
```

| Key | Meaning |
| --- | --- |
| `prep.commands` | Run **on the host**, in the worktree, once per worktree, before the sandbox exists. devcontainer's `initializeCommand` |
| `prep.target` | The guest platform offered to `prep.commands`. `auto` derives it from the image; `none` offers nothing |
| `cache.enabled` | Mount the host's package caches into the guest, read-only |
| `cache.managers` | Which caches. `auto` detects them from lockfiles |

`prep.commands` get `$BOXER_TARGET_FLAGS` (`--os=linux --cpu=arm64 --libc=musl`) and
`$BOXER_TARGET_OS`, `$BOXER_TARGET_CPU`, `$BOXER_TARGET_LIBC`. The flags are offered, never added to
your command.

<Callout type="warn">
`[prep]` is only safe for packages that ship prebuilt platform binaries. Anything that compiles at
install time (node-gyp, cgo) builds for the host and fails in the guest with `invalid ELF header`.
`boxer doctor` names such packages. Use `setup` when unsure.
</Callout>

`[cache]` cannot change a result: the install still runs in the guest, so only the download is
saved. See [environment](/docs/guides/environment).

## Setup and services

```toml
image_setup   = []        # example: ["npm i -g typescript"]
setup         = []        # example: ["npm ci"]
start         = []        # example: ["npm run dev"]
ready         = ""        # example: "curl -sf http://127.0.0.1:3000/"
ready_timeout = "60s"
```

| Key | Runs | Meaning |
| --- | --- | --- |
| `image_setup` | In the guest, as root, once per image; captured in the pack | Change the image: packages, global tools |
| `setup` | In the guest, once per worktree | Prepare the worktree: dependency installs |
| `start` | In the guest, detached, every time the sandbox starts, after `setup` | Services. Not supervised |
| `ready` | Polled until it exits 0 | Readiness probe before the sandbox is reported up |
| `ready_timeout` | | How long to poll `ready`. Exceeded: cause `NOT_READY` |

Dependency installs belong in `setup`, not `image_setup`: a pack carries the guest filesystem, and
the worktree is mounted from the host. See [environment](/docs/guides/environment). When `ready`
never passes, the services' output is in `/tmp/boxer-start.log` in the guest, and boxer quotes its
tail in the error.

## Environment

```toml
env_passthrough = ["CI"]
secrets         = []      # example: ["NPM_TOKEN"]

[env]                     # example
NODE_ENV = "development"
```

| Key | Meaning |
| --- | --- |
| `env` | Set in the guest for every command. Baked into the pack |
| `env_passthrough` | Host variables read at run time. Not baked into the pack |
| `secrets` | Like `env_passthrough`, and never written to a pack or an event |

`env_passthrough` and `secrets` are forwarded by name, so values never appear in an argument vector.
They reach `setup` and `image_setup` too.

## Network

```toml
[network]
mode        = "allowlist"   # on | off | allowlist
allow_hosts = []            # example: ["registry.npmjs.org"]
ports       = []            # example: ["auto:3000"]
dns         = ""            # "" | "off" | an address
```

| Key | Meaning |
| --- | --- |
| `network.mode` | `allowlist`: only `allow_hosts` plus the registry hosts needed to pull the image. `on`: open. `off`: no network. `allowlist` needs `smolvm` |
| `network.allow_hosts` | Hosts the guest may reach under `allowlist` |
| `network.ports` | Forwards, `host:guest`. `auto:<guest>` picks a free host port, so worktrees do not collide; `boxer status` shows where it landed |
| `network.dns` | Guest resolver. Empty: the host's caching resolver. `off`: smolvm's default public resolvers. An address: used as given |

## URLs

```toml
[urls]
enabled  = false
provider = "portless"     # the only provider
name     = ""             # base name; empty: the repository's directory name
names    = {}             # example: { "3000" = "web" }
```

| Key | Meaning |
| --- | --- |
| `urls.enabled` | Give each forwarded port a stable name through [portless](https://github.com/vercel-labs/portless), e.g. `https://fix-ui.myapp.localhost:1355` |
| `urls.provider` | What serves the names. Only `portless` |
| `urls.name` | Base hostname, before any worktree prefix |
| `urls.names` | Labels per guest port. With several ports, each is `<label>.<name>`; an unlabelled port uses its number. One port needs no label |

Requires `npm install -g portless`. Without it, boxer warns once and behaves as if `[urls]` were
off. See [URLs](/docs/guides/urls) for naming rules and lifecycle.

## Tasks

```toml
[tasks]                   # example
test  = "npm test"

[tasks.e2e]
cmd         = "npm run e2e"
description = "the browser suite; needs the dev server"
junit       = ["reports/junit.xml"]
timeout     = "10m"
env         = { HEADLESS = "1" }
```

A task is a command string, or a table with `cmd` (required) and any of `description`, `junit`,
`timeout` (a Go duration) and `env`. Unknown keys are errors. Run with `boxer run --task <name>`;
an unknown name is refused with cause `NO_SUCH_TASK`. See [tasks](/docs/guides/tasks).

## Test results

```toml
[results]

```

| Key | Meaning |
| --- | --- |
| `results.auto` | Worktree-relative JUnit XML paths or globs to summarise after every run |
| `results.fail_on_test_failures` | Exit 1 when the command passed but a test failed |

See [test results and capsules](/docs/guides/results).

## Lifecycle and housekeeping

```toml
create_on             = ["session_start", "run", "mcp"]
destroy_on            = []
reuse_existing        = true
warm_on_session_start = false
auto_reclaim          = true
reclaim_every         = "6h"
idle_timeout          = "2h"
min_free_gb           = 5
packs_keep_last       = 5
```

| Key | Meaning |
| --- | --- |
| `create_on` | Signals that provision a sandbox: `session_start`, `subagent_start`, `run`, `mcp` |
| `destroy_on` | Signals that delete it: `session_end`, `subagent_stop`, `never`. Empty: a sandbox outlives its session, and `gc` reclaims it when idle |
| `reuse_existing` | A new session attaches to the scope's existing sandbox. `false` builds a new one per create signal |
| `warm_on_session_start` | The session-start hook provisions in the background and returns at once |
| `auto_reclaim` | Ordinary commands run the `gc` sweep, at most once per `reclaim_every` |
| `reclaim_every` | Minimum interval between automatic sweeps |
| `idle_timeout` | A sandbox or pack unused this long is reclaimable. `"never"` disables the idle rule |
| `min_free_gb` | Free-disk margin. Below it, boxer skips writing a pack and pulls the image instead |
| `packs_keep_last` | Keep at most this many packs regardless of age. `0` keeps all the idle rule allows |

## Per-harness overrides

```toml
[harness.kimi]            # example
mode        = "tool"
enforcement = "hook"
isolation   = "session"
```

`[harness.<name>]` accepts only `mode`, `enforcement` and `isolation`. Everything else is
repository-wide.

## Telemetry

```toml
[telemetry]
enabled         = false
sink            = "none"    # none | file | stderr | otel
path            = ""        # file sink; empty: $XDG_STATE_HOME/boxer/events.jsonl
record_commands = false
endpoint        = ""        # otel only
```

| Key | Meaning |
| --- | --- |
| `telemetry.enabled` | Off by default: no log, no metrics, no network. `true` with `sink = "none"` means `file` |
| `telemetry.sink` | Where events go |
| `telemetry.path` | File sink path. Empty: `$XDG_STATE_HOME/boxer/events.jsonl`, else `~/.local/state/boxer/events.jsonl` |
| `telemetry.record_commands` | Keep command lines in events; otherwise they are redacted |
| `telemetry.endpoint` | OTLP endpoint. Only in a binary built with `-tags otel` |

See [events](/docs/reference/events).

## devcontainer.json

boxer reads `.devcontainer/devcontainer.json` (or `.devcontainer.json`) first; any key set in
`boxer.toml` overrides it.

| devcontainer.json | boxer.toml |
| --- | --- |
| `image` | `image` |
| `initializeCommand` | `prep.commands` (runs on the host, as the specification says) |
| `onCreateCommand` | `image_setup` |
| `updateContentCommand`, then `postCreateCommand` | `setup` |
| `postStartCommand` | `start` |
| `workspaceFolder` | `mount_at` |
| `forwardPorts` | `network.ports` as `auto:<port>` |
| `portsAttributes.<port>.requireLocalPort` | keeps that port fixed: `<port>:<port>` |
| `portsAttributes.<port>.label` | `urls.names` |
| `appPort` | `network.ports`, fixed, as Docker's `-p` is |
| `containerEnv`, `remoteEnv` | `env` (`remoteEnv` wins where both name a variable) |
| `mounts` | `mounts` (bind mounts only) |
| `remoteUser`, else `containerUser` | `user` |
| `hostRequirements.cpus`, `.memory` | `cpus`, `memory`, raised to the minimum, never lowered |

A command given as an object of named commands runs them in name order.

**Variables are resolved on the host**, in every string: `${localWorkspaceFolder}` and
`${localWorkspaceFolderBasename}` (this worktree), `${containerWorkspaceFolder}` and
`${containerWorkspaceFolderBasename}` (the mount), and `${localEnv:NAME}` or
`${localEnv:NAME:default}`. `${containerEnv:NAME}` resolves inside `remoteEnv` when `containerEnv`
defines the name. Anything else unresolvable on the host (another `${containerEnv:…}`,
`${devcontainerId}`) produces a warning, and the `env` value or mount that uses it is dropped.

**Refused by name**, with a warning; the setting has no effect:

| key | why |
| --- | --- |
| `features`, `build`, `dockerFile` | need an image build, which boxer does not do |
| `dockerComposeFile` | several containers; boxer runs one guest per worktree |
| `runArgs`, `privileged`, `capAdd`, `securityOpt` | would change the sandbox's own boundary |
| `workspaceMount` | boxer always mounts the worktree, at `mount_at` |
| `overrideCommand: false` | boxer never runs the image's own command; put it in `start` |
| `postAttachCommand` | nothing attaches to a sandbox |
| `init` | the guest already reaps what it starts |
| `hostRequirements.gpu` (unless `"optional"`) | no backend passes a GPU through |

**Ignored**, because they describe an editor rather than an environment: `name`,
`customizations`, `shutdownAction`, `userEnvProbe`, `otherPortsAttributes`, and `portsAttributes`
fields other than `label` and `requireLocalPort`. `waitFor` has no equivalent; use `ready`.
`hostRequirements.storage` is not checked; `min_free_gb` covers disk. `updateRemoteUserUID` is
always on: boxer makes `user` able to write the worktree, as described under [guest](#guest).
