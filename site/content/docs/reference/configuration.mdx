```toml
# boxer.toml at the repository root
image       = "node:24-bookworm-slim"
setup       = ["npm ci"]
start       = ["npm run dev"]
ready       = "curl -sf http://127.0.0.1:3000/"

[network]
mode        = "allowlist"
allow_hosts = ["registry.npmjs.org"]
ports       = ["auto:3000"]

[tasks]
test = "npm test"
```

Every key is optional. `boxer doctor` prints each resolved value and the file or variable it came
from.

## Files and precedence

boxer merges these in order, each overriding the one before.

1. Built-in defaults, as listed on this page.
2. `.devcontainer/devcontainer.json`, else `.devcontainer.json`, from the repository root, else the
   worktree root. See [the mapping](#devcontainerjson).
3. `$XDG_CONFIG_HOME/boxer/boxer.toml`, else `~/.config/boxer/boxer.toml`.
4. `boxer.toml` at the repository root (the main checkout).
5. `boxer.toml` at the worktree root, when it differs from the repository root.
6. [`BOXER_*` environment variables](#environment-variables).
7. The [`[harness.<name>]`](#harness-overrides) table for the harness making the call.

A later file replaces a list and merges into a table key by key. An unknown key is an error, so a
typo cannot weaken enforcement. An unknown top-level table is a warning, so a repository written for
a newer boxer still loads. A value outside its allowed set is an error that names the allowed
values.

## Scope

A [scope](/docs/concepts/scopes-and-packs#scope) is what one sandbox belongs to.

### `isolation`

`string`, default `"worktree"`. One of `repo`, `worktree`, `session`, `subagent`. Env `BOXER_ISOLATION`.

What a sandbox is keyed to. `session` and `subagent` need an id from the harness or the
[identity flags](/docs/reference/cli#identity-flags).

```toml
isolation = "session"
```

### `on_missing_id`

`string`, default `"degrade"`. One of `degrade`, `fail`. Env `BOXER_ON_MISSING_ID`.

What `session` or `subagent` isolation does with no id. `degrade` falls back from `subagent` to
`session` to `worktree` and warns; `fail` refuses with `SCOPE_UNRESOLVED`.

```toml
on_missing_id = "fail"
```

### `require_worktree`

`string`, default `"warn"`. One of `off`, `warn`, `require`. Env `BOXER_REQUIRE_WORKTREE`.

What happens in the main checkout rather than a linked worktree. `warn` runs and warns, `require`
refuses with `WORKTREE_REQUIRED`, `off` says nothing.

```toml
require_worktree = "require"
```

### `require_linked_worktree`

`bool`, default `false`.

Accepted and has no effect in this release. Use `require_worktree = "require"`.

### `worktree.manage`

`string`, default `"off"`. One of `off`, `detect`. Env `BOXER_WORKTREE_MANAGE`.

`detect` makes a session in the main checkout share the repository's sandbox, with a warning, until
it moves into a linked worktree. It applies only when `isolation = "worktree"`.

```toml
[worktree]
manage = "detect"
```

## Integration

### `integration`

`string`, default `"outside"`. One of `outside`, `inside`. Env `BOXER_INTEGRATION`.

`outside` runs the harness on the host and its commands in the sandbox. `inside` runs the harness in
the guest; `boxer shell` and `boxer acp` set it. See [running the harness inside](/docs/guides/inside).

```toml
integration = "inside"
```

### `mode`

`string`, default `"rewrite"`. One of `rewrite`, `tool`, `off`. Env `BOXER_MODE`.

What a hook does with an intercepted command. `rewrite` turns it into `boxer run -c '<command>'`.
`tool` denies it and names `boxer_run` and `boxer run`. `off` lets everything through.

```toml
mode = "tool"
```

### `enforcement`

`string`, default `"both"`. One of `hook`, `shim`, `both`, `audit`. Env `BOXER_ENFORCEMENT`.

Which mechanisms hold. With `shim` or `both`, a hook on a harness that cannot rewrite lets the bare
command reach the [shim](/docs/guides/enforcement#path-shims); with `hook`, it denies it. `audit`
makes hooks print `boxer: audit: would <action>` on stderr and allow everything.

```toml
enforcement = "hook"
```

### `on_sandbox_unavailable`

`string`, default `"fail"`. One of `fail`, `passthrough`. Env `BOXER_ON_SANDBOX_UNAVAILABLE`.

What `boxer run` does when the sandbox cannot be provisioned. `fail` refuses. `passthrough` runs
the command on the host, unsandboxed.

```toml
on_sandbox_unavailable = "passthrough"
```

## What gets sandboxed

### `intercept`

`[]string`, default below.

Programs whose commands run in the sandbox. A compound command is wrapped whole when any segment
starts with one of them. `["*"]` intercepts every program not in `passthrough`. Not settable from
the environment.

```toml
intercept = ["npm", "npx", "pnpm", "yarn", "bun", "bunx", "node", "deno",
             "python", "python3", "pip", "uv", "pytest", "cargo", "rustc",
             "go", "make", "cmake"]
```

<Callout type="warn">
Under `enforcement = "shim"` or `"both"`, `boxer shim install` writes a file for every entry. A
`node` or `python` shim shadows the interpreter of a harness written in that language, and the
harness fails at startup. Narrow the list to build tools first.
</Callout>

### `passthrough`

`[]string`, default `["git", "gh", "ssh", "boxer", "smolvm"]`.

Programs that always run on the host. A compound command with any passthrough segment is not
wrapped. Not settable from the environment.

```toml
passthrough = ["git", "gh", "ssh", "boxer", "smolvm", "terraform"]
```

## Backend

### `backend`

`string`, default `"smolvm"`. One of `smolvm`, `container`, `docker`, `podman`. Env `BOXER_BACKEND`.

The runtime that hosts sandboxes. A backend that lacks a capability refuses the setting that needs
it with cause `UNSUPPORTED`. Only `smolvm` supports `network.mode = "allowlist"`, the default, so
set `network.mode` with any other backend. See [backends](/docs/concepts/backends#what-each-can-do).

```toml
backend      = "docker"
network.mode = "on"
```

## Guest

### `image`

`string`, default `""`. Env `BOXER_IMAGE`.

The guest image: an OCI reference, or a local `docker save` archive or rootfs directory given as a
path starting `./`, `../`, `/` or `~/`, or `-` for stdin. A local image is not pulled. Empty picks
by the first lockfile found in the worktree.

| Lockfile | Image |
| --- | --- |
| `bun.lock`, `bun.lockb` | `oven/bun:1-slim` |
| `pnpm-lock.yaml`, `package-lock.json`, `yarn.lock` | `node:24-bookworm-slim` |
| `uv.lock`, `requirements.txt`, `pyproject.toml` | `python:3.12-slim-bookworm` |
| `Cargo.lock` | `rust:1-slim-bookworm` |
| `go.sum`, `go.mod` | `golang:1-alpine` |
| none | `debian:bookworm-slim` |

With `integration = "inside"` and no image, the default is
`mirror.gcr.io/library/node:24-bookworm-slim`. The inferred images carry no compiler; add one in
`image_setup`. See [choosing an image](/docs/guides/environment#choose-an-image).

```toml
image = "node:24-alpine"
```

### `smolfile`

`string`, default `""`. Env `BOXER_SMOLFILE`.

A smolvm Smolfile to build the guest from. Takes precedence over `image`. Other backends refuse it.

```toml
smolfile = "./Smolfile"
```

### `cpus`

`int`, default `4`. Env `BOXER_CPUS`.

Virtual CPUs for the guest.

```toml
cpus = 2
```

### `memory`

`string`, default `"4G"`. Env `BOXER_MEMORY`.

Guest memory: `4G`, `4096M`, or a bare number of MiB. A setup step that exits 137 ran out of it.

```toml
memory = "8G"
```

### `mount_at`

`string`, default `"/workspace"`. Env `BOXER_MOUNT_AT`.

Where the worktree is mounted in the guest. `boxer run` from a subdirectory runs in the matching
subdirectory. With `integration = "inside"` the worktree is mounted at its host path instead.

```toml
mount_at = "/src"
```

### `mounts`

`[]string`, default `[]`.

Extra host directories, as `host:guest` or `host:guest:ro`. A leading `~/` in the host half is
expanded. The worktree is always mounted.

```toml
mounts = ["~/.m2:/root/.m2:ro"]
```

### `user`

`string`, default `""`.

The guest user for `setup`, `start` and every command, as a name or `uid[:gid]`. Empty uses the
image's `USER`. `image_setup` always runs as root. When the user cannot write the worktree, boxer
gives it your host uid on smolvm and recreates the sandbox once with `--userns=keep-id` on podman.

```toml
user = "node"
```

## Prep

`[prep]` runs commands on the host while the sandbox boots. See
[dependencies](/docs/guides/environment#install-dependencies).

### `prep.commands`

`[]string`, default `[]`.

Run on the host with `sh -lc`, in the worktree, once per worktree, and again when the list or the
target changes. A failure stops provisioning with `PREP_FAILED`. The commands get
`BOXER_TARGET_OS`, `BOXER_TARGET_CPU`, `BOXER_TARGET_LIBC`, `BOXER_TARGET_FLAGS`
(`--os=linux --cpu=arm64 --libc=musl`) and `BOXER_WORKTREE`. boxer never adds the flags to your
command.

```toml
[prep]
commands = ["npm ci $BOXER_TARGET_FLAGS"]
```

<Callout type="warn">
`[prep]` is only safe for packages that ship prebuilt platform binaries. A package that compiles at
install time (node-gyp, cgo) builds for the host and fails in the guest with `invalid ELF header`.
`boxer doctor` names such packages.
</Callout>

### `prep.target`

`string`, default `"auto"`.

The guest platform offered to `prep.commands`. `auto` derives it from the image, `none` offers
nothing, and `os/cpu/libc` sets it.

```toml
[prep]
target = "linux/arm64/musl"
```

## Cache

### `cache.enabled`

`bool`, default `true`.

Mount the host's package caches into the guest, read-only. Installs still run in the guest, so only
the download is saved.

```toml
[cache]
enabled = false
```

### `cache.managers`

`[]string`, default `["auto"]`.

Which caches. `auto` detects them from lockfiles. Otherwise any of `npm`, `pnpm`, `yarn`, `bun`,
`uv`, `poetry`, `cargo`, `go`.

```toml
[cache]
managers = ["pnpm", "cargo"]
```

## Setup and services

See [environment](/docs/guides/environment) for when to use each.

### `image_setup`

`[]string`, default `[]`.

Commands that change the image, run in the guest as root, once per sandbox (on smolvm, once per host). On smolvm the result is
saved in the environment [pack](/docs/concepts/scopes-and-packs#packs), so the next worktree skips
them. A failure is `SETUP_FAILED`.

```toml
image_setup = ["apt-get update && apt-get install -y build-essential"]
```

### `setup`

`[]string`, default `[]`.

Commands that prepare this worktree, run in the guest as `user`, once per worktree and again when
the list changes. A pack never skips them, because the worktree is mounted from the host. A failure
is `SETUP_FAILED`.

```toml
setup = ["npm ci"]
```

### `start`

`[]string`, default `[]`.

Commands run detached every time the sandbox starts, after `setup`. They are not supervised. Their
output goes to `/tmp/boxer-start.log` in the guest. A step that cannot be launched is
`START_FAILED`.

```toml
start = ["npm run dev"]
```

### `ready`

`string`, default `""`.

A command polled in the guest until it exits 0, before the sandbox is reported up. Empty means no
wait.

```toml
ready = "curl -sf http://127.0.0.1:3000/"
```

### `ready_timeout`

`string` (Go duration), default `"60s"`.

How long to poll `ready`. When it passes, the command fails with `NOT_READY` and quotes the tail of
the start log.

```toml
ready_timeout = "3m"
```

## Environment

### `env`

`table` of strings, default `{}`.

Set in the guest for every command. Part of the environment pack's key and saved in the pack, so
keep secrets out of it.

```toml
[env]
NODE_ENV = "development"
```

### `env_passthrough`

`[]string`, default `["CI"]`.

Host variables forwarded to the guest by name at run time, when the host sets them. Values never
enter a command line, a pack or an event. They reach `setup` and `image_setup` too.

```toml
env_passthrough = ["CI", "DEBUG"]
```

### `secrets`

`[]string`, default `[]`.

Forwarded exactly like `env_passthrough`. List credentials here so the file says which variables
are secrets. See [secrets](/docs/concepts/security#secrets).

```toml
secrets = ["NPM_TOKEN"]
```

## Network

### `network.mode`

`string`, default `"allowlist"`. One of `allowlist`, `on`, `off`. Env `BOXER_NETWORK_MODE`.

`allowlist` lets the guest reach `allow_hosts` plus the registry hosts its image pull needs.
`on` is open, `off` is no network. `allowlist` needs `backend = "smolvm"`.

```toml
[network]
mode = "on"
```

### `network.allow_hosts`

`[]string`, default `[]`.

Hosts the guest may reach under `allowlist`. A failed command names the hosts the allowlist refused,
and `boxer doctor` lists them under `denied_hosts`.

```toml
[network]
allow_hosts = ["registry.npmjs.org", "github.com"]
```

### `network.ports`

`[]string`, default `[]`.

Port forwards as `host:guest`, bound to `127.0.0.1`. `auto:<guest>` takes a free host port, so
worktrees do not collide; `boxer status` shows where it landed. `NO_FREE_PORT` when none is free.

```toml
[network]
ports = ["auto:3000", "5432:5432"]
```

### `network.dns`

`string`, default `""`.

The guest resolver on smolvm. Empty uses the host's caching resolver, `off` uses smolvm's default
public resolvers, and an address is used as given.

```toml
[network]
dns = "10.0.0.2"
```

## URLs

`[urls]` names forwarded ports through [portless](https://github.com/vercel-labs/portless). See
[URLs](/docs/guides/urls).

### `urls.enabled`

`bool`, default `false`. Env `BOXER_URLS` (a boolean).

Give each forwarded port a stable name, such as `https://fix-ui.myapp.localhost:1355`. Needs
`portless` on the host; without it boxer warns and runs as if this were off.

```toml
[urls]
enabled = true
```

### `urls.provider`

`string`, default `"portless"`. One of `portless`.

What serves the names.

```toml
[urls]
provider = "portless"
```

### `urls.name`

`string`, default `""`.

The base hostname, before the worktree prefix. Empty uses the repository's directory name.

```toml
[urls]
name = "shop"
```

### `urls.names`

`table` of strings, default `{}`.

A label per guest port, giving `<label>.<name>`. One forwarded port needs no label; several
unlabelled ports are named by their number.

```toml
[urls]
names = { "3000" = "web", "8080" = "api" }
```

## Tasks

### `tasks.<name>`

`string` or `table`, default none.

A named command line, run with `boxer run --task <name>`. The table form takes `cmd` (required),
`description`, `junit` (paths or globs), `timeout` (a Go duration) and `env`; any other key is an
error. An empty `cmd` or a bad `timeout` is an error. See [tasks](/docs/guides/tasks).

```toml
[tasks]
test = "npm test"

[tasks.e2e]
cmd         = "npm run e2e"
description = "the browser suite; needs the dev server"
junit       = ["reports/junit.xml"]
timeout     = "10m"
env         = { HEADLESS = "1" }
```

## Results

See [test results](/docs/guides/results).

### `results.auto`

`[]string`, default `[]`.

Worktree-relative JUnit XML paths or globs to summarise after every `boxer run`. A task's `junit`
and the `--junit` flag take precedence.

```toml
[results]
auto = ["reports/*.xml"]
```

### `results.fail_on_test_failures`

`bool`, default `false`.

Exit 1 when the command exited 0 and a test in the reports failed. A non-zero exit is never
changed.

```toml
[results]
fail_on_test_failures = true
```

## Lifecycle

### `create_on`

`[]string`, default `["session_start", "run", "mcp"]`.

Signals that may create a sandbox. Any of `session_start`, `subagent_start`, `run`, `mcp`. Without
`run`, `boxer run` fails with `NO_SANDBOX` until `boxer up` has run.

```toml
create_on = ["session_start", "subagent_start", "run", "mcp"]
```

### `destroy_on`

`[]string`, default `[]`.

Hook signals that delete the sandbox. Any of `session_end`, `subagent_stop`, `never`. Empty keeps
the sandbox after the session, for `gc` to reclaim when idle.

```toml
destroy_on = ["session_end"]
```

### `reuse_existing`

`bool`, default `true`.

Accepted and has no effect in this release. A scope always reuses its sandbox.

### `warm_on_session_start`

`bool`, default `false`. Env `BOXER_WARM_ON_SESSION_START`.

The session-start hook provisions in a detached `boxer up` and returns at once, so the session
never waits for a create.

```toml
warm_on_session_start = true
```

## Reclaiming

### `auto_reclaim`

`bool`, default `true`.

Ordinary commands start the [`gc`](/docs/reference/cli#boxer-gc) sweep in the background, at most
once per `reclaim_every`. `BOXER_NO_RECLAIM=1` skips it for one process.

```toml
auto_reclaim = false
```

### `reclaim_every`

`string` (Go duration), default `"6h"`.

The minimum interval between automatic sweeps.

```toml
reclaim_every = "1h"
```

### `idle_timeout`

`string` (Go duration or `"never"`), default `"2h"`.

A sandbox or environment pack unused this long is reclaimable. `never` turns the idle rule off.
`gc` reads it from the current directory's configuration.

```toml
idle_timeout = "24h"
```

### `min_free_gb`

`float`, default `5`.

Free disk boxer keeps. Below it, boxer skips writing a pack and pulls the image instead, and
`boxer doctor` warns. `0` turns the check off.

```toml
min_free_gb = 20
```

### `packs_keep_last`

`int`, default `5`.

Keep at most this many environment packs, whatever their age. `0` keeps every pack the idle rule
allows.

```toml
packs_keep_last = 2
```

## Harness overrides

### `harness.<name>`

`table`, default none.

Overrides for one harness, applied after every file and variable. Only `mode`, `enforcement` and
`isolation` are accepted. `<name>` is the harness name `boxer install` takes, and the call selects
it with `--harness` or `BOXER_HARNESS`.

```toml
[harness.kimi]
mode        = "tool"
enforcement = "hook"
isolation   = "session"
```

## Telemetry

See [events](/docs/reference/events).

### `telemetry.enabled`

`bool`, default `false`.

Record events. Off means no log, no metrics and no network. `true` with `sink = "none"` uses `file`.

```toml
[telemetry]
enabled = true
```

### `telemetry.sink`

`string`, default `"none"`. One of `none`, `file`, `stderr`, `otel`. Env `BOXER_TELEMETRY_SINK`.

Where events go. Setting the variable to anything but `none` also sets `enabled`.

```toml
[telemetry]
sink = "stderr"
```

### `telemetry.path`

`string`, default `""`.

The file sink's path. Empty uses `$XDG_STATE_HOME/boxer/events.jsonl`, else
`~/.local/state/boxer/events.jsonl`. `BOXER_TRACE` overrides it.

```toml
[telemetry]
path = "/tmp/boxer-events.jsonl"
```

### `telemetry.record_commands`

`bool`, default `false`.

Keep command lines, `argv`, `env` and `setup` in event payloads. Otherwise each is replaced by its
length, as `command_len` and so on.

```toml
[telemetry]
record_commands = true
```

### `telemetry.endpoint`

`string`, default `""`.

The OTLP endpoint for `sink = "otel"`. Only a binary built with `-tags otel` has that sink.

```toml
[telemetry]
sink     = "otel"
endpoint = "http://127.0.0.1:4318"
```

## Environment variables

Eighteen scalar keys can be set from the environment, for a harness that offers no other way to
configure a subprocess. Lists and tables cannot. A variable overrides every file, and a
`[harness.<name>]` table overrides the variable. `boxer doctor` names the variable as the source.

| Variable | Key |
| --- | --- |
| `BOXER_BACKEND` | `backend` |
| `BOXER_ISOLATION` | `isolation` |
| `BOXER_ON_MISSING_ID` | `on_missing_id` |
| `BOXER_REQUIRE_WORKTREE` | `require_worktree` |
| `BOXER_WORKTREE_MANAGE` | `worktree.manage` |
| `BOXER_INTEGRATION` | `integration` |
| `BOXER_MODE` | `mode` |
| `BOXER_ENFORCEMENT` | `enforcement` |
| `BOXER_ON_SANDBOX_UNAVAILABLE` | `on_sandbox_unavailable` |
| `BOXER_IMAGE` | `image` |
| `BOXER_SMOLFILE` | `smolfile` |
| `BOXER_MOUNT_AT` | `mount_at` |
| `BOXER_CPUS` | `cpus` (an integer) |
| `BOXER_MEMORY` | `memory` |
| `BOXER_NETWORK_MODE` | `network.mode` |
| `BOXER_URLS` | `urls.enabled` (a boolean) |
| `BOXER_TELEMETRY_SINK` | `telemetry.sink`, and `telemetry.enabled` unless the value is `none` |
| `BOXER_WARM_ON_SESSION_START` | `warm_on_session_start` (a boolean) |

A value that does not parse as its type is ignored. Variables with no key are listed in the
[CLI reference](/docs/reference/cli#environment-variables).

## devcontainer.json

boxer reads the part of a devcontainer file that needs no image build. It is the lowest file layer,
so any key `boxer.toml` sets wins. Comments and trailing commas are accepted.

| devcontainer.json | boxer.toml |
| --- | --- |
| `image` | `image` |
| `initializeCommand` | `prep.commands`, on the host, as the specification says |
| `onCreateCommand` | `image_setup` |
| `updateContentCommand`, then `postCreateCommand` | `setup` |
| `postStartCommand` | `start` |
| `workspaceFolder` | `mount_at` |
| `forwardPorts` | `network.ports` as `auto:<port>`. A `"service:port"` string uses the port |
| `portsAttributes.<port>.requireLocalPort` | That forward kept fixed, as `<port>:<port>` |
| `portsAttributes.<port>.label` | `urls.names` |
| `appPort` | `network.ports`, fixed, as Docker's `-p` is |
| `containerEnv`, `remoteEnv` | `env`. `remoteEnv` wins where both name a variable |
| `mounts` | `mounts`, bind mounts only |
| `remoteUser`, else `containerUser` | `user` |
| `hostRequirements.cpus`, `hostRequirements.memory` | `cpus`, `memory`, raised to the minimum, never lowered |

A command given as a string or an array is one line. An object of named commands becomes one line
per name, in name order.

Variables are resolved on the host in every string: `${localWorkspaceFolder}` and
`${localWorkspaceFolderBasename}` (this worktree), `${containerWorkspaceFolder}` and
`${containerWorkspaceFolderBasename}` (the mount), and `${localEnv:NAME}` or
`${localEnv:NAME:default}`, also spelled `${env:NAME}`. `${containerEnv:NAME}` resolves inside
`remoteEnv` when `containerEnv` defines the name. Another `${containerEnv:NAME}` or
`${devcontainerId}` gets a warning, and an `env` value or mount that uses it is dropped.

These are refused with a warning and have no effect.

| Key | Why |
| --- | --- |
| `features`, `build`, `dockerFile` | They need an image build, which boxer does not do |
| `dockerComposeFile` | It runs several containers; boxer runs one guest per worktree |
| `runArgs`, `privileged`, `capAdd`, `securityOpt` | They would change the sandbox's own boundary |
| `workspaceMount` | boxer always mounts the worktree, at `mount_at` |
| `overrideCommand: false` | boxer never runs the image's own command; put it in `start` |
| `postAttachCommand` | Nothing attaches to a sandbox |
| `init` | The guest already reaps what it starts |
| `hostRequirements.gpu`, unless `false` or `"optional"` | No backend passes a GPU through |

Every other key is ignored, including `name`, `customizations`, `shutdownAction`,
`userEnvProbe`, `otherPortsAttributes`, `waitFor` (use `ready`) and `hostRequirements.storage`
(`min_free_gb` covers disk). boxer always makes `user` able to write the worktree, as
`updateRemoteUserUID` asks.
