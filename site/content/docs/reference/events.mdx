---
title: Events
description: The JSON event stream boxer writes when telemetry is on, its schema, and how to read it.
---

boxer can record what it did as a stream of JSON events. The stream is off by default: with no
`[telemetry]` table and no `BOXER_TRACE`, boxer writes no events.

```toml
[telemetry]
enabled = true
sink = "file"               # none | file | stderr | otel
path = ""                   # default: $XDG_STATE_HOME/boxer/events.jsonl
record_commands = false     # command lines stay out of the stream unless this is true
endpoint = ""               # otel only; without it nothing leaves the machine
```

`BOXER_TRACE=<path>` turns the file sink on at that path regardless of configuration. The
evaluation harness uses it, and it is the quickest way to see what boxer is deciding. `enabled =
true` with no `sink` uses the file sink.

## Shape

```json
{
  "time": "2026-09-20T14:31:09.236Z",
  "event": "provision",
  "scope": "sb-7e1852e4a3c3",
  "harness": "claude-code",
  "duration_ms": 623.4,
  "outcome": "ok",
  "payload": { "created": true, "image": "node:24-bookworm-slim" }
}
```

| `event` | |
| --- | --- |
| `resolve` | a scope was resolved from a directory and an identity |
| `provision` | a sandbox was created or started |
| `pack` | an environment pack was written or reused |
| `run` | a command ran in the guest |
| `rewrite` | a hook replaced a command with its sandboxed form |
| `deny` | a command was refused |
| `hook` | a hook was invoked |
| `mcp` | an MCP tool was called |
| `gc` | a sweep ran |
| `error` | something failed outside the other names |

`outcome` is `ok`, `error`, `denied` or `skipped`. `payload` holds event-specific fields.

`duration_ms`, `scope`, `harness`, `outcome` and `payload` are omitted when empty. Treat a missing
field as absent, not as a default, and ignore event names you do not recognise: names are added,
never repurposed.

Command lines are omitted unless `record_commands = true`. The separate last-run record is covered
in the [security model](/docs/concepts/security#what-boxer-records).

## Reading it back

```sh
boxer logs -n 50          # this scope
boxer logs --json         # the raw events
boxer logs --scope NAME   # another sandbox
```
