---
title: Glossary
description: Short definitions of the terms boxer's documentation uses, each linked to the page that covers it.
---

**ACP (Agent Client Protocol).** The protocol an editor uses to drive a coding agent as a
subprocess over stdio. `boxer acp <harness>` starts the harness's ACP server inside the guest; see
[Running the harness inside](/docs/guides/inside).

**Adherence.** How often a live model follows the brief when nothing enforces it and the prompt
never mentions boxer. Measured by its own [evaluation tier](/docs/evals).

**Backend.** The runtime that runs sandboxes: `smolvm` (default), Apple `container`, `docker` or
`podman`. See [Backends](/docs/concepts/backends).

**Brief.** A generated summary of how this checkout runs commands: the mount, the mode, the
intercept and passthrough lists, and the declared tasks. `boxer brief` prints it, the hooks inject
it, and the [MCP server](/docs/reference/mcp#resource) serves it at `boxer://brief`.

**Capsule.** A `capsule.toml` recording a failure well enough to rerun it: the command, the commit,
the relevant configuration, and what counts as reproducing it. `boxer capsule replay` exits 0 when
it still fails; see [Test results and capsules](/docs/guides/results).

**Cell.** One row of an evaluation matrix: one harness at one integration level running one task
in its own worktree and sandbox. See [The matrix tier](/docs/evals/matrix).

**Enforcement.** Which interception mechanisms are live: `hook`, `shim`, `both` or `audit`. See
[Enforcement](/docs/guides/enforcement).

**Fork.** A copy-on-write child of a running smolvm sandbox. Children share the parent's worktree.
See [Forking](/docs/guides/forking).

**Guest.** Inside the sandbox. The **host** is your machine.

**Harness.** A coding agent's CLI, such as Claude Code, Codex or OpenCode. See
[Harnesses](/docs/start/harnesses).

**`image_setup`, `setup` and `[prep]`.** Three command lists. `image_setup` changes the guest
image and is cached in the pack; `setup` prepares the worktree and runs per worktree; `[prep]` runs
on the host before the sandbox exists. See [Environment](/docs/guides/environment#dependencies).

**Inside and outside.** Where the harness runs. **Outside**, the default, the harness runs on the
host and boxer sandboxes the commands it issues. **Inside** (`integration = "inside"`), the harness
runs in the guest. See [Running the harness inside](/docs/guides/inside).

**Integration level.** One of five ways a command reaches the guest: MCP and skill, hooks, the
OpenCode plugin, PATH shims, and inside mode. They stack; `boxer install` picks the strongest the
harness supports. See [Harnesses](/docs/start/harnesses).

**Intercept.** The list of program names boxer sandboxes. **Passthrough** is the list that
stays on the host.

**Isolation.** What a scope is keyed to: `repo`, `worktree` (default), `session` or `subagent`.

**Mode.** What boxer does with a command it catches: `rewrite` turns it into `boxer run`, `tool`
denies the shell and leaves the `boxer_run` MCP tool, `off` does nothing.

**Named pack.** A pack saved with `boxer pack save`. `gc` never removes it.

**Orchestrator.** A tool that creates a worktree per task and starts a harness in it, such as
Conductor or OpenHands. See [Orchestrators](/docs/guides/orchestrators).

**Pack.** A snapshot of a smolvm guest after `image_setup` has run, reused by the next sandbox with
the same environment. See [Scopes and packs](/docs/concepts/scopes-and-packs#packs).

**Placement.** Inside or outside. Part of the scope key, so the two placements of one worktree get
two sandboxes.

**Rewrite.** Replacing a command with its sandboxed form before it runs, so the agent sees the
command's output rather than a refusal.

**Scope.** The identity of one sandbox: `sb-` plus twelve hex characters, also the sandbox's name.
The two words printed beside it (`swift-crab`) come from the same hash. See
[Scopes and packs](/docs/concepts/scopes-and-packs).

**Shim.** A file on `PATH` named after a program, which reruns the command in the guest. Works with
no harness cooperation, as long as `PATH` holds.

**Skill.** The Agent Skill boxer installs, telling the agent to run commands through boxer. It asks
rather than enforces.

**smolvm.** The microVM runtime boxer uses by default. See [Backends](/docs/concepts/backends).

**Task.** A named command line in `[tasks]`, run with `boxer run --task <name>`. See
[Tasks](/docs/guides/tasks).

**Tier.** One level of evaluation (`t1`, `t2`, `adherence`, `flow`, `sdlc`, `matrix`). See
[How boxer is evaluated](/docs/evals/strategy).

**Worktree.** A git working tree. boxer's default unit of isolation.
