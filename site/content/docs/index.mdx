---
title: What boxer is
description: One sandbox per git worktree, so a coding agent's shell commands run there instead of on your machine.
---

Coding agents run shell commands — `npm install`, `make`, `python script.py` — as you, on your
machine, with your credentials and filesystem.

boxer runs them in a sandbox instead: one per git worktree, created on the first command, with the
worktree mounted at `/workspace`. The default sandbox is a [smolvm](https://smolmachines.com)
microVM with its own kernel; Apple `container`, docker and podman are
[alternatives](/docs/concepts/backends) with different isolation and cost.

The agent does not need to know. It runs `npm test`; the command runs in the sandbox, from the
matching directory under the mount, and returns the same exit code, stdout and stderr.

```console
$ boxer run -c 'uname -a'
Linux sb-7f2a91 6.12.95 #1 SMP aarch64 Linux
```

(The host here is a Mac.)

## What it is not

- **Not a guard for your code.** The worktree is mounted read-write, because the agent is there to
  change it. boxer protects everything else on the machine.
- **Not a container runtime or dev environment.** It sits between the agent and its commands. The
  machines, images and snapshots belong to the backend; boxer keeps only small records, removed with
  the sandbox.
- **Not a defence against a deliberate attacker.** The threat model is an agent being careless or
  destructive, not one trying to escape. [Security model](/docs/concepts/security) says where the
  line is.
