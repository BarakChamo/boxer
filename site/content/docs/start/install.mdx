Install a backend, install boxer, and run one command to check both.

## Requirements

- macOS on Apple Silicon, or Linux on x86-64 or arm64. Windows is not supported.
- A git repository to work in. boxer keys each sandbox to a git worktree.
- For smolvm, hardware virtualisation. On Linux that is a `/dev/kvm` your user can open, usually
  through the `kvm` group (`sudo usermod -aG kvm $USER`, then log in again). Inside a Linux VM, that
  VM needs nested virtualisation.

A harness that sandboxes its own process, such as Codex's seatbelt, blocks the hypervisor.
[Enforcement](/docs/guides/enforcement#harnesses-that-sandbox-themselves) has the flags that turn it off.

## 1. Install a backend

smolvm is the default. It gives each sandbox its own kernel and is the only backend with an egress
allowlist, environment packs and forks.

```sh
curl -sSL https://smolmachines.com/install.sh | bash
smolvm --version
```

To use a runtime you already have, install it and set `backend` in `boxer.toml`:

| Backend | Install | Then | `boxer.toml` |
| --- | --- | --- | --- |
| Apple `container` (macOS 26, Apple Silicon) | `brew install container` | `container system start` and `container system kernel set --recommended` | `backend = "container"`, `network.mode = "on"` |
| docker | Docker Desktop or OrbStack on macOS, the docker engine on Linux | | `backend = "docker"`, `network.mode = "on"` |
| podman | `brew install podman`, or your distribution's package | on macOS, `podman machine init && podman machine start` with the `applehv` provider | `backend = "podman"`, `network.mode = "on"` |

Only smolvm enforces the default `network.mode = "allowlist"`. The other three refuse it by name, so
choose `"on"` or `"off"` for them. [Backends](/docs/concepts/backends) compares what each one
isolates and enforces.

## 2. Install boxer

```sh
curl -fsSL https://raw.githubusercontent.com/BarakChamo/boxer/main/install.sh | sh
```

The script downloads the release for your platform into `~/.local/bin`, checks its sha256 against
the release's `checksums.txt`, and prints the `PATH` line to add if that directory is not on it.
`BOXER_VERSION=v1.0.0` pins a release and `BOXER_INSTALL_DIR` changes the destination.

Other routes install the same binary:

```sh
go install github.com/BarakChamo/boxer/cmd/boxer@latest
npm i -g https://github.com/BarakChamo/boxer/releases/download/v1.0.0/boxer-cli-1.0.0.tgz
```

Each release also builds a Homebrew cask and the `boxer-cli` npm package. Neither is published to a
tap or the npm registry yet.

## 3. Check it

```sh
cd your-repository
boxer doctor
boxer run -c 'uname -a'
```

`boxer doctor` prints what boxer resolved for this directory: the worktree, the backend, the image
it will boot, the integrations it can see, and anything that will not work. `boxer run` prints
`Linux`: the command ran in the sandbox. The first run creates the sandbox and pulls its image, so
it takes longest. `boxer backends --probe` runs a real sandbox on every installed backend.

## Optional: portless

```sh
npm install -g portless
```

[`[urls]`](/docs/guides/urls) uses it to give each worktree's dev server a stable name. Without it,
forwarded ports still work.
