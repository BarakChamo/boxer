title: Install

boxer is a single Go binary. It needs a backend to run sandboxes ([smolvm](https://smolmachines.com)
by default) and a git repository to work in.

Supported hosts are macOS on Apple Silicon and Linux on x86-64 or arm64. Windows is not supported:
boxer's worktree model depends on POSIX paths and mounts.

smolvm needs hardware virtualisation: on Linux that means `/dev/kvm`. boxer cannot start a microVM
from inside another sandbox that blocks it, such as a harness's own seatbelt. See
[Enforcement](/docs/guides/enforcement#harnesses-that-sandbox-themselves).

## Install smolvm

```sh
curl -sSL https://smolmachines.com/install.sh | bash
smolvm version
```

The rest of this page assumes `smolvm` is on your `PATH`.

### Or another backend

smolvm gives each sandbox its own kernel and is the only backend that enforces an egress allowlist.
To use a runtime you already have, install it as below and set `backend` in `boxer.toml`
(`container`, `docker` or `podman`). [Backends](/docs/concepts/backends) says what each one can and
cannot do.

| backend | install | then |
| --- | --- | --- |
| Apple `container` (macOS 26, Apple Silicon) | `brew install container`, or the installer from its [releases](https://github.com/apple/container/releases) | `container system start`, `container system kernel set --recommended` |
| docker | Docker Desktop or OrbStack | — |
| podman | `brew install podman` | `podman machine init && podman machine start` (use the `applehv` provider on a Mac) |

`boxer backends --probe` starts a real sandbox on each installed backend to confirm it works.

### Optional: portless, for dev-server URLs

```sh
npm install -g portless
```

Only needed for [`[urls]`](/docs/guides/urls). Without it, forwarded ports still work but have no
names.

## Install boxer

Every route installs the same binary.

```sh
# Install script: downloads the release for your platform into ~/.local/bin and
# checks its sha256 against the release's checksums.txt.
curl -fsSL https://raw.githubusercontent.com/BarakChamo/boxer/main/install.sh | sh

# npm, from the tarball attached to the release. It downloads the same release binary.
npm i -g https://github.com/BarakChamo/boxer/releases/download/v1.0.0/boxer-cli-1.0.0.tgz

# From source, with a Go toolchain.
go install github.com/BarakChamo/boxer/cmd/boxer@latest
```

Each release also builds a Homebrew cask and the `boxer-cli` npm package, but neither is published
to a tap or the npm registry yet.

`BOXER_VERSION=v1.2.3` pins the install script to a release, and `BOXER_INSTALL_DIR` changes where
it puts the binary. If that directory is not on your `PATH`, the script prints the line to add. It
also warns if `smolvm` is missing.

## Check it

```sh
cd your-repository
boxer doctor
```

`doctor` prints what boxer resolved for this directory: the scope (the git worktree the sandbox is
keyed to), the image it would boot, the harness integrations it can see, and anything that will not
work. Run it again whenever a command does not end up in the sandbox.

```sh
boxer run -c 'uname -a'
```

This prints `Linux`: the command ran in the guest. The first command in a worktree creates its VM,
which takes longest the first time, while the image is pulled. Later commands reuse the running VM.
[Your first sandbox](/docs/start/first-run) explains what happened.
