---
title: Orchestrators
description: "Set up boxer for tools that create a worktree per task: T3 Code, Paperclip, herdr, Conductor, Multica, OpenHands."
---

An orchestrator opens a worktree for each task and starts a harness in it. boxer keys a sandbox
to the worktree, so each task gets its own sandbox, removed with the worktree. What differs per
orchestrator is how it launches the harness, and so which
[integration level](/docs/guides/enforcement) applies.

## Warm the sandbox first

```sh
boxer install git
```

This writes a `post-checkout` hook (honouring `core.hooksPath`) that runs `boxer up --detach` in
every worktree `git worktree add` creates, so the VM is booting before any harness opens it.

Use it with any orchestrator that creates a worktree and launches into it at once. Without it, T3
Code's provider fails with `turn/setPermissionMode failed` while a cold VM boots (32 to 39
seconds).

`boxer install all` does not touch git configuration, so run this separately.

## T3 Code

Cuts a worktree and runs Claude Code in it. The project layer is inherited, so
a committed `boxer install claude-code` is the whole integration.

```sh
boxer install claude-code
git add .claude .mcp.json && git commit -m 'boxer'
boxer install git                                    # warm each new worktree
```

Commit the files: the orchestrator creates its worktree from a branch, so the integration must be
in that branch.

## Paperclip

Launches its harness over ACP with its own environment. The committed project layer is inherited
as with T3 Code, but boxer's trace variable is not, so run `boxer doctor` in the task worktree to
confirm the integration is active.

## herdr

Drives a harness interactively in a terminal pane:

- herdr starts the harness, so there is no command line to add `--permission-mode` to. Grant
  permissions in project settings, and include `Skill`: boxer installs a skill, and using one needs
  its own permission. A pane waiting on `Use skill "boxer"?` looks like a hang.
- `terminal.default_shell` can point at `boxer-bash` (from `boxer shim install --shell`), which
  puts every pane's shell in the sandbox. This works for a person typing in a pane, but herdr will
  not attach its own agent to such a pane: it identifies a pane by its foreground process, which is
  then `boxer`, not a shell.

## Conductor

Conductor runs each harness's real binary against an ordinary git worktree.

**Try the project layer first.** If Conductor inherits it, as other tools using real worktrees do,
the ordinary install is the whole integration:

```sh
boxer install claude-code
git add .claude .mcp.json && git commit -m 'boxer'
```

**Otherwise, put the harness in the VM.**

```sh
boxer install conductor        # writes .conductor/settings.toml
```

That writes a managed block pointing `claude_code_executable_path` and the other harness paths at
harness shims. Conductor spawns the shim, the shim runs `boxer shell <harness>`, and the harness
runs [in the VM](/docs/guides/inside).

<Callout>
Conductor's local workspaces are GUI-only, and its CLI drives cloud workspaces where boxer has
nothing to sandbox, so this integration is verified by hand, not by the evals.
</Callout>

## Multica

Multica runs a daemon that creates a worktree per issue. Point its runtime profile at a boxer
harness shim, so the harness runs in the VM:

```sh
boxer shim install --harness claude ~/.boxer/shims
multica runtime profile create --command-name claude
multica runtime profile set-path claude ~/.boxer/shims/claude
```

Prefer the profile over `MULTICA_CLAUDE_PATH`: it survives a daemon restart and applies to every
task. Start the daemon from a shell with `boxer` on `PATH`.

<Callout type="warn">
**Untested.** Multica's daemon needs a configured server, which the evaluation host did not have,
so its eval cell reports as skipped. The steps above follow from what the binary reads.
</Callout>

## OpenHands

OpenHands lets you set its terminal's shell, so the agent's whole terminal can be the sandbox
with no boxer integration in the harness:

```sh
boxer shim install --shell ~/.boxer/shims     # writes boxer-bash
```

Point the terminal tool's `shell_path` at it.
