---
title: Troubleshooting
description: Common failures, what causes them, and how to fix them.
---

Start with `boxer doctor`. It resolves the same configuration a real command would and reports
setups that look right but will not hold.

## A command ran on the host

Check, in order:

1. **No integration in effect.** `boxer doctor` shows whether one is installed for this harness
   and enforcing. If not, `boxer install <harness>`.
2. **The program is not on `intercept`.** Only listed programs are sandboxed. Add it.
3. **The harness uses a login shell.** `zsh -lc` rebuilds `PATH` and puts system binaries ahead
   of shims; `doctor` reports this. Use hooks or tool mode ([enforcement](/docs/guides/enforcement)).
4. **Codex in a linked worktree.** Codex reads project config from the main repository, so a
   `.codex/` in the worktree alone is never read. `boxer install codex` writes both.

## The sandbox will not start

- **`read checkpoint footer: I/O error`.** A truncated environment pack, left by an interrupted
  `pack create`. boxer usually detects and rebuilds it; `boxer up --rebuild` forces it.
- **`exit 137` during setup.** The out-of-memory killer. Raise `memory` in `boxer.toml` or run
  fewer sandboxes at once.

## A download or install fails inside the sandbox

**Cause:** the default `network.mode` is `allowlist`, and a refused connection looks like an
ordinary DNS or connect error in the guest. boxer names the refused host after the command:

```console
$ boxer run -c 'npm ci'
npm error network request to https://registry.npmjs.org/... failed
boxer: the egress allowlist refused registry.npmjs.org during this command
boxer: fix: add it to network.allow_hosts in boxer.toml, or set network.mode = "on"
```

**Fix:** do what the `fix:` line says. If you are not sure which command was refused, `boxer doctor`
lists every host the machine refused under `denied:`.

## Setup ran but dependencies are missing

**Cause:** the install is in `image_setup`, which is captured in the image, not in the worktree.
**Fix:** move dependency installs to `setup`. See [environment](/docs/guides/environment).

## The dev server does not answer

- **`boxer up` passed but the server is not ready.** `ready` is too weak a probe. The server's
  output is in `/tmp/boxer-start.log` in the guest, and boxer quotes its tail in the error. boxer
  starts `start` once per boot and does not restart a service that dies.
- **The forwarded port does not answer.** The server is bound to `127.0.0.1` in the guest.
  A `ready` probe inside the guest still passes. Bind `0.0.0.0`.
- **An agent started a second server.** It could not reach the one you told it about. Inside the
  guest the server is at `127.0.0.1:<guest port>`; a host-forwarded port means nothing there.
- **A `[urls]` name refuses the connection.** The portless proxy is down. Any `boxer` command
  restarts it; by hand, `portless proxy start --port 1355`.
- **A `[urls]` name answers 404.** The name is not registered: the sandbox predates `[urls]`, or its
  route was removed by hand. `boxer down && boxer up`; `boxer status` prints the name.
- **`boxer: warning: urls.enabled is set but portless is not installed`.** `npm install -g
  portless`. Ports are still forwarded meanwhile.
- **Next.js refuses or warns about its dev chunks.** Add `allowedDevOrigins: ['127.0.0.1',
  'localhost']` for a forwarded port, and `'*.localhost'` for a `[urls]` name. See
  [URLs](/docs/guides/urls#nextjs).

## An interactive harness hangs

**Cause:** it is waiting on a dialog headless runs never show: a permission prompt, a
bypass-permissions confirmation, or a skill approval. **Fix:** read the pane, and grant every tool
the agent needs in project settings, `Skill` included.

## The first run is slow

**Cause:** the image is pulled and `image_setup` runs. Later starts reuse the pack. If the second
run is also slow, the pack key changed: `image_setup`, `env`, `mounts`, `start` and `ready` are all
part of it.

## Disk is full

```sh
boxer ls --resources
boxer gc --all
```

`boxer doctor` prints what boxer uses on disk.
