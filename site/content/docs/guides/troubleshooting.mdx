---
title: Troubleshooting
description: Common boxer failures, with the symptom, the cause and the fix for each.
---

Run `boxer doctor` first. It resolves the same configuration a real command would and reports
setups that look right but will not hold.

```sh
boxer doctor
```

## A command ran on the host

**Symptom:** `uname` in the agent prints `Darwin`, or a file the command wrote appears outside the
worktree.

**Cause and fix**, in the order to check:

1. **No integration is in effect.** `boxer doctor` shows whether one is installed for this harness
   and enforcing. If not, run `boxer install <harness>`.
2. **The program is not on `intercept`.** Only listed programs are sandboxed. Add it to `intercept`
   in `boxer.toml`.
3. **The harness uses a login shell.** `zsh -lc` rebuilds `PATH` and puts system binaries ahead of
   shims, and `boxer doctor` reports this. Switch to hooks or tool mode
   ([integration levels](/docs/guides/enforcement)).
4. **Codex in a linked worktree.** Codex reads project config from the main repository, so a
   `.codex/` in the worktree alone is never read. Run `boxer install codex` from the worktree, which
   writes both, or `boxer install codex --user`.
5. **Project hooks are not trusted.** Codex and Grok ignore project hooks until the folder is
   trusted. Run `/hooks` once in Codex, or launch Grok once with `--trust`.

## The sandbox will not start

**Symptom:** `read checkpoint footer: I/O error`.

**Cause:** a truncated environment pack, left by an interrupted `pack create`. boxer usually detects
and rebuilds it.

**Fix:** `boxer up --rebuild`.

**Symptom:** `exit 137` during setup.

**Cause:** the guest's out-of-memory killer.

**Fix:** raise `memory` in `boxer.toml` (default `4G`), or run fewer sandboxes at once.

**Symptom:** the default configuration is refused on docker, podman or Apple `container`.

**Cause:** those backends cannot enforce `network.mode = "allowlist"`, the default.

**Fix:** set `network.mode` to `"on"` or `"off"` ([backends](/docs/concepts/backends)).

## A download or install fails inside the sandbox

**Symptom:** an ordinary DNS or connect error in the guest, followed by a line from boxer:

```console
$ boxer run -c 'npm ci'
npm error network request to https://registry.npmjs.org/... failed
boxer: the egress allowlist refused registry.npmjs.org during this command
boxer: fix: add it to network.allow_hosts in boxer.toml, or set network.mode = "on"
```

**Cause:** the allowlist refused the host.

**Fix:** do what the `fix:` line says. `boxer doctor` lists every host the allowlist refused under
`denied:`.

## Setup ran but dependencies are missing

**Symptom:** a second worktree starts with no `node_modules`.

**Cause:** the install is in `image_setup`, which is saved in the pack, and the worktree is not.

**Fix:** move dependency installs to `setup` ([environment](/docs/guides/environment#install-dependencies)).

## The dev server does not answer

**Symptom:** `boxer up` passed but the server is not ready.

**Cause:** the `ready` probe passed before the server could serve. boxer runs `start` once per boot
and does not restart a service that dies.

**Fix:** make `ready` probe the real endpoint. The server's output is in `/tmp/boxer-start.log` in
the guest, and boxer quotes its tail in the error.

**Symptom:** the forwarded port on the host does not answer, but `ready` passes.

**Cause:** the server is bound to `127.0.0.1` in the guest.

**Fix:** bind it to `0.0.0.0` in the guest. The host side stays on `127.0.0.1`.

**Symptom:** an agent started a second server.

**Cause:** it could not reach the one you told it about. Inside the guest the server is at
`127.0.0.1:<guest port>`, and the host-forwarded port does not exist there.

**Fix:** give the agent the guest port, or turn on [`[urls]`](/docs/guides/urls) and let it run
`boxer url`.

**Symptom:** a `[urls]` name refuses the connection.

**Cause:** the portless proxy is down, for example after a reboot.

**Fix:** the next `boxer up` or `boxer run` in that worktree restarts it on port 1355. By hand, run
`portless proxy start --port 1355`.

**Symptom:** a `[urls]` name answers 404.

**Cause:** the name is not registered. The sandbox predates `[urls]`, or its route was removed by
hand.

**Fix:** `boxer down && boxer up`. `boxer status` prints the name.

**Symptom:** `boxer: warning: urls.enabled is set but portless is not installed`.

**Cause:** portless is not on `PATH`. Ports are still forwarded.

**Fix:** `npm install -g portless`.

**Symptom:** Next.js refuses or warns about its dev chunks.

**Cause:** the request's origin is not in `allowedDevOrigins`.

**Fix:** add `'127.0.0.1'` and `'localhost'` for a forwarded port, and `'*.localhost'` for a `[urls]`
name ([URLs](/docs/guides/urls#nextjs)).

## An interactive harness hangs

**Symptom:** a harness in a terminal pane (herdr, for example) stops with no output.

**Cause:** it is waiting on a dialog headless runs never show: a permission prompt, a
bypass-permissions confirmation, or a skill approval such as `Use skill "boxer"?`.

**Fix:** read the pane, and grant every tool the agent needs in project settings, `Skill` included.

## The harness fails to start in inside mode

**Symptom:** `boxer shell claude` stops with a message about the macOS Keychain.

**Cause:** the Linux guest has no Keychain, so a Keychain login does not travel.

**Fix:** run `claude setup-token` on the host and export `CLAUDE_CODE_OAUTH_TOKEN`
([inside mode](/docs/guides/inside#what-it-costs)).

**Symptom:** the harness is missing or broken after an interrupted first run.

**Cause:** the one-time install in the guest did not finish.

**Fix:** `boxer up --recreate`, then `boxer shell <harness>` again.

## The first run is slow

**Symptom:** the first `boxer up` in a repository takes minutes, and so does the second.

**Cause:** the first run pulls the image and runs `image_setup`, and later starts reuse the pack. If
the second run is also slow, the pack key changed. `image_setup`, `env`, `mounts`, `start` and
`ready` are all part of it ([packs](/docs/concepts/scopes-and-packs#the-key)).

**Fix:** keep those stable. Packs exist on smolvm only, so on other backends `image_setup` runs once
per sandbox.

## The disk is full

**Symptom:** boxer skips packing with a free-space message, or the host runs out of disk.

**Cause:** stopped sandboxes and old packs.

**Fix:** see what boxer uses, then reclaim stopped sandboxes and unreferenced packs. Running
sandboxes are kept.

```sh
boxer ls --resources
boxer gc --all
```
