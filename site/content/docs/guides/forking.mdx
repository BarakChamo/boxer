---
title: Fork a sandbox
description: Branch a running sandbox into warm copy-on-write children for sharded work.
---

`boxer fork` branches the running sandbox into children that share its memory and disks
copy-on-write. A child does not boot: it starts from the parent's running state, with dependencies
installed and services already up. Forking needs the smolvm backend.

```sh
boxer fork --prepare --count 4
boxer run --scope swift-crab-f1 -c 'npm test -- --shard=1'
boxer fork rm --all
```

## Know that children share the worktree

A child inherits its parent's mounts and cannot override them, and smolvm refuses to branch a
machine whose mount is staged:

```
fork: staged mounts cannot be branched yet because multiple descendants would
synchronize into the same host directory
```

Every fork of a worktree sees the same files, and two children writing one file race each other
as two processes on your machine would.

<Callout type="warn">
Use forks for work that shards cleanly, such as test shards that write to separate paths. For work
that edits the same files, use a second git worktree, which gets its own sandbox and its own files.
</Callout>

## Prepare the sandbox

A sandbox can only be forked if it was started as a branch source (`smolvm machine start
--branchable`). Preparing restarts the sandbox, which ends whatever is running in it, so boxer asks
for it explicitly with `--prepare`:

```console
$ boxer fork
boxer: this sandbox was not started as a branch source, so it cannot be forked. Preparing restarts it, which ends whatever is running in it
  scope:     swift-crab (sb-7e1852e4a3c3, worktree)
  worktree:  /Users/me/src/myapp
  cause:     NOT_FORKABLE
  fix:       boxer fork --prepare
```

Branchability lasts for one boot, so a sandbox that has been stopped needs `--prepare` again.

## Work with children

```sh
boxer fork ls                             # this scope's children
boxer run --scope <name> -c '<command>'   # run in one
boxer fork rm <name>                      # remove one
boxer fork rm --all                       # remove them all
```

A child is named after its parent (`sb-7e1852e4a3c3-f1` or `swift-crab-f1`), and either form works
with `--scope`. A child has no worktree of its own, so it is addressed by name rather than from a
directory.

`--count` is how many children the scope should have, so asking twice for four makes four.
`boxer ls` shows children beside sandboxes, `boxer gc` reclaims a child whose parent is gone, and
each child costs what a sandbox costs.

## Save state across hosts

A fork does not persist. smolvm can write a `.smolcheckpoint` of RAM and processes, but refuses on
any machine with a host mount, and boxer always mounts the worktree. To carry a prepared
filesystem between hosts, save a [named pack](/docs/concepts/scopes-and-packs#packs-you-name).
