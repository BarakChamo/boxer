---
title: Worktrees and parallel work
description: Run several agents in parallel, one worktree and one sandbox each.
---

boxer gives each git worktree its own sandbox, so parallel agents need only parallel worktrees.

```sh
git worktree add ../myapp-feature -b feature
cd ../myapp-feature
boxer run -c 'npm test'      # its own VM, its own port, its own filesystem
```

With the default `isolation = "worktree"`, two worktrees never share a sandbox, so two agents cannot overwrite each other's `node_modules`,
race on a port, or see each other's half-finished files.

## Committing a boxer.toml

Every worktree cut from a branch inherits that branch's `boxer.toml`, so keep it free of
host-specific values. Ports are the usual one:

```toml
[network]
ports = ["auto:3000"]     # not "3000:3000"
```

A fixed host port fails with a busy-address error as soon as a second worktree starts.

## Finding each worktree's dev server

`auto:` gives every worktree its own host port, so none of them is at `localhost:3000`.
`boxer status` says where each one landed. To give them names instead, turn on `[urls]`:

```toml
[network]
ports = ["auto:3000"]

[urls]
enabled = true            # needs portless: npm install -g portless
```

```console
$ boxer up
boxer: url: https://fix-ui.myapp.localhost:1355 -> guest port 3000
```

The main checkout is `myapp.localhost`, a worktree on a branch is `<branch>.myapp.localhost`, and a
detached worktree (what most orchestrators create) uses the sandbox's two-word name in place of a
branch. Names last as long as the sandbox. Agents read them from `boxer status --json` or the
`boxer_status` tool. [URLs](/docs/guides/urls) covers the setup and the naming rules.

## What each worktree pays

Each sandbox has its own memory and disk. The default allocation is `cpus = 4` and
`memory = "4G"`, so four sandboxes ask for 16 GB.

Measured, four concurrent node sandboxes held about 4 GB resident and 2.7 GB of disk: roughly a
gigabyte and 700 MB each. The host has to be able to cover the allocation, not only the resident
use, so lower it if you run several:

```toml
cpus   = 2
memory = "2G"
```

`boxer ls --resources` prints allocation and resident use side by side. Packs add 130 to 365 MB
each, and `packs_keep_last` (default 5) bounds how many are kept. `boxer gc` reclaims idle
sandboxes and unreferenced packs.

## Orchestrators

Tools that cut a worktree per task (Conductor, T3 Code, Paperclip, herdr) get a sandbox per task
with no extra setup, as long as the boxer integration is committed on the branch they cut from. See
[Orchestrators](/docs/guides/orchestrators).

<Callout type="warn">
Codex reads hooks from the main repository, not the linked worktree. Use `boxer install codex`
rather than copying hooks into a worktree; see [Connect your harness](/docs/start/harnesses).
</Callout>
