---
title: Test results and capsules
description: Summarise JUnit results after a run, and save a failure as a capsule someone else can replay.
---

boxer can summarise a run's JUnit reports, so you see which tests failed without reading the log,
and save the last run as a **capsule**: a file that someone else can replay to check whether the
failure still happens. Neither does anything unless you use it.

## Which tests failed

Point a run at its JUnit XML and boxer parses it after the command exits:

```sh
boxer run --junit junit.xml -- npm test
```

```console
boxer: tests 128 passed, 3 failed, 1 error, 2 skipped (1 file(s))
boxer:   FAIL api/AuthTest.refresh
boxer:   FAIL cart/CheckoutTest.applies_discount
boxer:   FAIL cart/CheckoutTest.rejects_expired
```

Failed and errored tests are both listed as `FAIL`, sorted, up to ten. boxer reads the report on
the host: the worktree is mounted, not copied, so the file the guest wrote is already there.

Three ways to say where the reports are, highest precedence first:

```sh
boxer run --junit junit.xml,reports/*.xml -- npm test   # this run
```

```toml
[tasks.test]
cmd   = "npm test"
junit = ["reports/junit.xml"]     # whenever this task runs

[results]
auto = ["junit.xml", "reports/*.xml"]   # every run in this repository
fail_on_test_failures = true
```

Patterns are relative to the worktree. `*` matches; `**` does not recurse.

Two rules:

- **Counts come from the test cases, not the attributes.** boxer counts `<testcase>` elements and
  their `<failure>`, `<error>` and `<skipped>` children, and ignores `tests=` and `failures=` on
  `<testsuite>`, which frameworks fill in inconsistently.
- **A report older than the run is ignored**, so a command that crashed before writing one does
  not report the previous run's results.

### Failing on test failures

By default the run's exit code is the command's, and the summary is informational.
`--fail-on-test-failures`, or `results.fail_on_test_failures`, turns exit 0 into 1 when the report
has failures or errors. A non-zero exit code is never replaced.

## Capsules

Every run leaves a record for its sandbox: the command, directory, exit code, image, pack, HEAD,
whether the tree was dirty, the tail of stdout and stderr, and the test summary if there was one.
`boxer status --json` shows it as `last_run`. `boxer capsule new` turns it into a file.

```console
$ boxer run -c 'npm test'            # it fails
$ boxer capsule new
boxer: wrote capsule.patch (4.1 kB)
boxer: wrote capsule.toml — exit 1 from "npm test"
boxer: replay it with `boxer capsule replay capsule.toml`
```

`capsule.toml` records what ran, against which commit, under which image and configuration, and
what outcome counts as reproducing the failure. If the tree was dirty, the uncommitted changes are
written beside it as `capsule.patch`. Commit it, attach it to an issue, or delete it.

```sh
boxer capsule inspect capsule.toml
boxer capsule replay capsule.toml
```

A replay overlays the captured configuration onto the current one and runs the command again:

```console
boxer: reproduced — exit 1, as recorded
```

**Exit 0 means the failure reproduced**, and exit 1 means it did not. This is the reverse of a
test: replay answers "does this still fail?".

Replay refuses, with exit 1, a worktree with uncommitted changes (override with `--allow-dirty`) or
a HEAD other than the captured one (`--allow-drift`). A captured patch is applied only with
`--apply-patch`.

### What a capsule is not

It does not contain a machine. A capsule describes the environment; to keep a prepared guest, use a
[named pack](/docs/concepts/scopes-and-packs).
