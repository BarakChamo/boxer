The repository's [`examples/`](https://github.com/BarakChamo/boxer/tree/main/examples) directory
has a `boxer.toml` for each common setup. Each is a **runnable** project, a **config** to drop into
an existing one, or a **program** that uses boxer as a library. The test suite loads every
`boxer.toml` and `devcontainer.json` there, and every `boxer.toml` except `monorepo`'s has been run
on a real sandbox.

| example | kind | shows |
| --- | --- | --- |
| `nextjs` | config | a Next.js dev server per worktree, `[urls]`, `allowedDevOrigins`, tasks |
| `nextjs-devcontainer` | config | the same from `devcontainer.json` plus a short `boxer.toml`: users, port labels, variables |
| `vite` | runnable | Vite with `--strictPort`, a name per worktree |
| `python-fastapi` | runnable | uv: a tool in `image_setup`, the project in `setup` |
| `go-api` | runnable | a Go service, tasks for test and vet |
| `monorepo` | config | two services in one sandbox, named ports, JUnit-reporting tasks |
| `host-prep` | config | installing on the host with `[prep]`, and when not to |
| `docker-backend` | config | the same project on docker or podman, and what that gives up |
| `go-embed` | program | `pkg/boxer` running one command in several worktrees at once |

A runnable example must be its own git repository, because boxer keys a sandbox to a worktree:

```sh
cp -R examples/go-api /tmp/go-api && cd /tmp/go-api
git init -q && git add -A && git commit -qm init
boxer up && curl -sk "$(boxer url)"
```

The snippets below are trimmed. The files carry comments and more tasks, and each directory's
`README.md` lists its gotchas.

## Next.js

```toml
image = "mirror.gcr.io/library/node:24-alpine"
setup = ["npm ci --no-audit --no-fund"]
start = ["npx next dev -p 3000 -H 0.0.0.0"]
ready = "node -e \"fetch('http://127.0.0.1:3000/').then(r=>process.exit(r.ok?0:1),()=>process.exit(1))\""
ready_timeout = "240s"

[network]
allow_hosts = ["registry.npmjs.org"]
ports = ["auto:3000"]

[urls]
enabled = true

[tasks.test]
cmd = "npm test"
description = "the unit tests"
```

```ts
// next.config.ts
const nextConfig = { allowedDevOrigins: ["127.0.0.1", "localhost", "*.localhost"] };
export default nextConfig;
```

`boxer up`, then `boxer url`. In a second worktree the same file gives a second server at
`https://<branch>.<repo>.localhost:1355`, with its own `node_modules` and `.next`.

## Python with uv

```toml
image = "mirror.gcr.io/library/python:3.12-slim"
image_setup = ["pip install --no-cache-dir uv"]   # a tool: once, kept in the pack
setup = ["uv sync"]                               # the project: once per worktree, into .venv
start = ["uv run uvicorn main:app --host 0.0.0.0 --port 8000"]
ready = "python -c \"import urllib.request,sys; sys.exit(0 if urllib.request.urlopen('http://127.0.0.1:8000/').status == 200 else 1)\""
ready_timeout = "120s"

[network]
allow_hosts = ["pypi.org", "files.pythonhosted.org"]
ports = ["auto:8000"]

[urls]
enabled = true
```

Installing uv changes the image, so it is `image_setup`: run once and cached for every worktree.
The project's dependencies land in this worktree's `.venv`, so they are `setup`. See
[environment](/docs/guides/environment).

## Go

```toml
image = "mirror.gcr.io/library/golang:1.24-alpine"
start = ["go run ."]
ready = "wget -q -O /dev/null http://127.0.0.1:8080/"
ready_timeout = "120s"

[network]
ports = ["auto:8080"]

[urls]
enabled = true

[tasks.test]
cmd = "go test ./..."
description = "the Go tests"
```

With module dependencies, add `go mod download` to `setup` and `"proxy.golang.org"` and
`"sum.golang.org"` to `allow_hosts`.

## From a devcontainer

boxer reads `.devcontainer/devcontainer.json` as its first layer. A short `boxer.toml` beside it
adds what devcontainer has no key for, above all the allowlist, since boxer's default network
reaches only the image registry:

```toml
[network]
allow_hosts = ["registry.npmjs.org"]

[urls]
enabled = true
```

## Embedding boxer in Go

`go-embed` opens a sandbox per worktree with `pkg/boxer`, runs one shell line in all of them at
once, and prints each exit code. Run it from a boxer checkout:

```sh
go run ./examples/go-embed -- 'npm test' ~/code/app-wt1 ~/code/app-wt2
```

Each directory must be a git worktree, and each reads its own `boxer.toml`.
[Building on boxer](/docs/guides/building-on-boxer) and the [Go reference](/docs/reference/go) cover
the API.

## What every example has in common

- **The server binds `0.0.0.0`.** A forwarded port arrives on the guest's interface, so a server
  on `127.0.0.1` never sees it.
- **Ports are `auto:`.** A fixed host port makes the second worktree fail to start.
- **`ready` probes the server.** `boxer up` returns when the server answers.
- **The allowlist names only the package registry.** The image registry is allowed
  automatically, and a failed install names any host that is missing.
