---
title: Declare tasks
description: Name the commands an agent should run, so it runs them in the sandbox by name instead of composing its own.
---

A task is a named command line in `boxer.toml` that always runs in the guest. Hooks and shims catch
a command by its first word, so `npm test` is caught and `NODE_ENV=test ./node_modules/.bin/jest`
runs on the host. A task does not depend on that match.

```toml
[tasks]
test    = "npm test"
build   = "npm run build"
lint    = "npm run lint"
migrate = "npm run db:migrate"
```

```sh
boxer run --task test
```

boxer looks the name up in `boxer.toml` and runs that command in the guest. Nothing is parsed or
matched.

## Describe a task

A task can be a table instead of a string. The two forms can be mixed in one `[tasks]` table:

```toml
[tasks]
lint = "npm run lint"

[tasks.test]
cmd         = "npm test"
description = "the unit suite; no services needed"
junit       = ["reports/junit.xml"]
timeout     = "10m"
```

| Key | What it does |
| --- | --- |
| `cmd` | the command line, as the string form |
| `description` | what the task is for; `boxer tasks` prints it and the brief gives it to the agent, which uses it to choose between tasks |
| `junit` | where this task's JUnit XML lands, so `boxer run --task test` summarises it without being told |
| `timeout` | a Go duration that bounds the command, so a hung task fails instead of holding the session |
| `env` | variables set for this task only, on top of `[env]`, for example `env = { NODE_ENV = "test" }` |

A misspelled key inside a task table is an error, like every other key in `boxer.toml`.

## How an agent finds them

The boxer skill tells the agent to use tasks first, and the **brief**, the summary of this
worktree's sandbox that hooks inject at session start, lists each task with its description.

An unknown name is refused with the real names in the error, and nothing runs on the host:

```console
$ boxer run --task tests
boxer: no task named "tests" in boxer.toml
  scope:     swift-crab (sb-7e1852e4a3c3, worktree)
  worktree:  /Users/me/src/demo
  cause:     NO_SUCH_TASK
  fix:       boxer run --task build | lint | migrate | test
```

Every boxer error has this shape; the `fix:` line is the next command to try. To list tasks:

```sh
boxer tasks           # name and description, or the command line when there is no description
boxer tasks --json    # the same, for a tool
boxer brief           # the mount, the mode, the intercept list, and the tasks with what they are for
```

`boxer brief --json` keeps `tasks` as a map of name to command line, and puts descriptions, JUnit
paths and timeouts in `task_details`.

## Write the command line

boxer runs a task with `sh -c` in the guest directory that matches your current one, so pipes, `&&`
and environment prefixes work:

```toml
[tasks]
test-one = "npm test -- --runTestsByPath"
ci       = "npm run lint && npm test && npm run build"
seed     = "DATABASE_URL=postgres://localhost/dev npm run seed"
```

`--task` names the whole command. Adding `-c` or trailing arguments is refused:

```console
$ boxer run --task test -- --watch
boxer run: --task names the whole command; do not add -c or arguments
```

Declare a separate task for the variant you need.

## Choose what to declare

Declare what an agent reaches for and would get wrong by guessing: test, build, lint and
typecheck, plus steps such as a migration, codegen or a fixture reset. Leave out anything
destructive you would rather approve by hand, because an agent runs a declared task without asking.

## How reliably an agent uses them

The adherence evaluation gives an agent a repository with one described task and a prompt that
never mentions boxer, then checks whether it ran the task or composed its own command. On
2026-09-25, across four models per harness:

| harness | used the task |
| --- | --- |
| Claude Code, Codex, Pi | 3 of 4 models |
| DSH, OpenCode | 2 of 4 |
| Copilot, Grok, Kimi | 0 of 4 |

On Copilot, Grok and Kimi the brief does not reliably reach the model, so an agent there runs a
task only when the prompt names it. A declared task does not stop an agent composing its own
command; hooks and shims keep that command in the sandbox. The per-cell results are in
`docs/eval-adherence.md`, and the method is in [Results](/docs/evals/results#when-boxer-only-asks).
