---
title: Name each worktree's dev server
description: Give each worktree's dev server a stable hostname, and tell every agent where its own one is.
---

`[urls]` gives each forwarded port a hostname per worktree, such as
`https://fix-ui.myapp.localhost:1355`, through [portless](https://github.com/vercel-labs/portless),
a local reverse proxy that routes by hostname. Without it, each worktree's `auto:` port is a
different number that a person or agent has to look up.

## Turn on URLs

```sh
npm install -g portless
```

```toml
start = ["npx next dev -p 3000 -H 0.0.0.0"]

[network]
ports = ["auto:3000"]

[urls]
enabled = true
```

```console
$ boxer up
boxer: url: https://fix-ui.myapp.localhost:1355 -> guest port 3000
```

The server must listen on `0.0.0.0` inside the guest; see
[Forward ports](/docs/guides/environment#forward-ports).

## How names are chosen

| worktree | URL |
| --- | --- |
| the main checkout | `https://myapp.localhost:1355` |
| a linked worktree on branch `fix-ui` | `https://fix-ui.myapp.localhost:1355` |
| a detached worktree, or one whose name is taken | `https://swift-crab.myapp.localhost:1355` |

`myapp` is the repository's directory name, or `urls.name`. portless supplies the branch prefix.
It gives a detached worktree (what most orchestrators create) no prefix, and gives two branches
ending in the same segment (`feat/login`, `fix/login`) the same one, so in those cases boxer uses
the sandbox's two-word name. boxer never takes a name another sandbox or a person registered.

With several ports, each is named `<label>.<repo>`, after the branch prefix. The label comes from
`urls.names`, a devcontainer's `portsAttributes.label`, or the port number:

```toml
[network]
ports = ["auto:3000", "auto:8080"]

[urls]
enabled = true
names   = { "3000" = "web", "8080" = "api" }   # fix-ui.web.myapp.localhost, fix-ui.api.myapp.localhost
```

## How agents find it

```sh
boxer url          # the first forwarded port's address
boxer url 8080     # a specific guest port
boxer open         # open it in a browser
```

The brief tells the agent to run `boxer url` instead of assuming `localhost:<port>`, and so do the
skill and `AGENTS.md`. The `boxer_status` MCP tool returns each port's URL, and `boxer status
--json` and `boxer ls --json` have them under `urls`.

A harness running [inside](/docs/guides/inside) the sandbox cannot reach the names, because the
proxy is on the host's loopback. It is told its server is at `127.0.0.1:<port>`, and that the
address a person should open is in `$BOXER_URLS` (`3000=https://…`).

In the adherence evaluation, where an agent is told only that a dev server is running and asked to
fetch its home page, five of eight harnesses reached it by name on all four models; see
[Results](/docs/evals/results#when-boxer-only-asks).

## When names are added and removed

boxer registers a name when the sandbox starts and removes it when `down`, `rm` or `gc` deletes
the sandbox. `gc` also removes a route whose sandbox disappeared some other way.

If the portless proxy is not running, boxer starts it on port 1355, or on `PORTLESS_PORT` when that
is set to 1024 or above, and stops it when the last route goes. A proxy you started yourself is
left running. The proxy binds `127.0.0.1`; see
[forwarded ports and URLs](/docs/concepts/security#forwarded-ports-and-urls).

Without portless installed, `boxer up` prints a warning and everything else works. Ports are still
forwarded, and `boxer url` prints `http://127.0.0.1:<host port>`.

## Next.js

Next.js 15 serves the page, its chunks and hot reload through the name, but warns that a future
version will refuse cross-origin dev requests. `*.localhost` covers every worktree's name:

```ts
// next.config.ts
const nextConfig = { allowedDevOrigins: ["127.0.0.1", "localhost", "*.localhost"] };
export default nextConfig;
```

[`examples/nextjs`](/docs/guides/examples#nextjs) is a complete setup.
