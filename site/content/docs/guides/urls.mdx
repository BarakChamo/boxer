---
title: Dev servers and URLs
description: Give each worktree's dev server a stable hostname, and tell every agent where its own one is.
---

`[urls]` gives each forwarded port a hostname per worktree, such as
`https://fix-ui.myapp.localhost:1355`, through [portless](https://github.com/vercel-labs/portless),
a local reverse proxy that routes by hostname. Without it, `auto:` ports give every worktree a
different host port that nobody, person or agent, knows without asking.

## Turn it on

```sh
npm install -g portless
```

```toml
start = ["cd app && npx next dev -p 3000 -H 0.0.0.0"]
ready = "node -e \"fetch('http://127.0.0.1:3000/').then(r=>process.exit(r.ok?0:1),()=>process.exit(1))\""

[network]
mode  = "on"
ports = ["auto:3000"]

[urls]
enabled = true
```

```console
$ boxer up
boxer: url: https://fix-ui.myapp.localhost:1355 -> guest port 3000
```

The server must listen on `0.0.0.0` inside the guest. A forwarded port arrives on the guest's
network interface, so a server bound to `127.0.0.1` never sees it.

## What each worktree is called

| worktree | URL |
| --- | --- |
| the main checkout | `https://myapp.localhost:1355` |
| a linked worktree on branch `fix-ui` | `https://fix-ui.myapp.localhost:1355` |
| a detached worktree, or one whose name is taken | `https://swift-crab.myapp.localhost:1355` |

`myapp` is the repository's directory name, or `urls.name`. The branch prefix comes from portless.
portless gives a detached worktree (what most orchestrators create) no prefix, and two branches
ending in the same segment (`feat/login`, `fix/login`) the same one, so in those cases boxer uses
the sandbox's two-word name instead. It never takes a name another sandbox or a person already
registered.

With several ports, each is named `<label>.<repo>`. The label comes from `urls.names`, a
devcontainer's `portsAttributes.label`, or the port number:

```toml
[network]
ports = ["auto:3000", "auto:8080"]

[urls]
enabled = true
names   = { "3000" = "web", "8080" = "api" }   # web.myapp…, api.myapp…
```

## Where agents learn it

- the brief every harness shows the agent before its first action: run `boxer url`, not
  `localhost:<port>`;
- the skill and `AGENTS.md`;
- the `boxer_status` MCP tool, which returns each forwarded port's URL;
- `boxer url [port]`, which prints the address, and `boxer open`, which opens it in a browser;
- `boxer status --json` and `boxer ls --json`, under `urls`.

A harness running [inside](/docs/guides/inside) the sandbox cannot reach the names, because the
proxy is on the host's loopback. It is told its server is at `127.0.0.1:<port>`, and that the
address a person should open is in `$BOXER_URLS` (`3000=https://…`).

In a live eval where an agent is told only that a dev server is running and asked to fetch its
home page, five of the eight harnesses found it by name on all four models tried. See
[strategy](/docs/evals/strategy).

## Lifecycle

A name is registered when the sandbox starts and removed when it is deleted by `down`, `rm`, `gc`
or `down --all`. `gc` also removes a route whose sandbox disappeared some other way. If the portless
proxy is not running, boxer starts it on port 1355 (never 443, which needs sudo), and stops it
again when the last route is removed. A proxy you started yourself is left running. The proxy
listens on loopback only; see [forwarded ports and URLs](/docs/concepts/security#forwarded-ports-and-urls).

Without portless installed, boxer warns once and everything else works: ports are still forwarded,
and `boxer url` prints `http://127.0.0.1:<host port>`.

## Next.js

Next.js 15 serves the page, its chunks and hot reload through the name, but logs a warning that a
future version will refuse cross-origin dev requests. One setting covers every worktree's name:

```ts
// next.config.ts
const nextConfig = { allowedDevOrigins: ["*.localhost"] };
export default nextConfig;
```

A complete setup is in [Examples](/docs/guides/examples).
