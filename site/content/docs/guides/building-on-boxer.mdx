Orchestrators, dashboards and new harness integrations can drive boxer through three entry
points. Pick by what you are writing:

| You are writing | Use |
| --- | --- |
| A Go program that owns sandbox lifecycle | [`pkg/boxer`](#go) |
| Anything else that needs to read state | [`--json`](#json) |
| An integration for a harness | [the CLI](#the-cli-as-an-interface) |

## Go

```go
import "github.com/BarakChamo/boxer/pkg/boxer"
```

The only importable package; everything else is under `internal/`. It is a thin facade over the
same code the CLI runs.

<Callout>
Experimental until 1.0, and covered by the stability contract from 1.0 onwards.
</Callout>

```go
b, err := boxer.Open(cwd, boxer.Options{Harness: "claude-code", SessionID: sid})
if err != nil {
    var be *boxer.Error
    if errors.As(err, &be) {
        log.Fatalf("%s (%s): %s", be.Reason, be.Cause, be.Fix)
    }
    log.Fatal(err)
}

for _, w := range b.Warnings() {
    log.Println("boxer:", w)   // main checkout, degraded isolation
}

if _, err := b.Ensure(true, false); err != nil {   // create if needed, then start
    log.Fatal(err)
}

code, err := b.Run(
    []string{"sh", "-c", "npm test"},
    boxer.RunOpts{Stdin: os.Stdin, Stdout: os.Stdout, Stderr: os.Stderr},
)
```

`Options` carries the harness name and the identity (`SessionID`, `AgentID`). All may be empty.
They matter when `isolation` keys the sandbox to something other than the worktree (see
[scopes](/docs/concepts/scopes-and-packs)), and when a `[harness.<name>]` override should apply.

### Handling refusals

Every refusal is a `*boxer.Error` with four fields: `Reason` and `Fix` for a person, `Cause` for a
program, and `Scope` for context. Match on `Cause`, which is stable, not on the message.

`Run` returns `-1` with an error when `on_sandbox_unavailable = "passthrough"` and the sandbox
could not be provisioned. Your caller decides whether to fall back to the host.

### Host-wide operations

```go
machines, _ := boxer.List()          // every boxer-owned machine
_ = boxer.Stop("sb-7e1852e4a3c3")
_ = boxer.Delete("sb-7e1852e4a3c3")
t := boxer.LastUsed("sb-7e1852e4a3c3")
```

These take a machine name rather than a working directory, since the worktree may already be
gone.

## JSON

For anything that is not Go. `--json` on `ls`, `status`, `down`, `gc`, `doctor`, `brief`, `tasks`,
`logs`, `backends`, `integrations`, `stop`, `rm`, `pack ls`, `fork` and `capsule inspect` prints exactly one JSON document on stdout.
Fields are added, never repurposed or removed. See [JSON output](/docs/reference/json) for the
shapes.

```sh
boxer ls --json --resources     # every sandbox, with live cpu and memory
boxer status --json             # this scope; exit 0 running, 3 stopped, 4 absent
boxer doctor --json             # the resolved configuration and every check
```

A health check can use the `status` exit code without parsing anything.

### Watching instead of polling

```sh
boxer watch --json
```

One JSON object per line for each state change (created, running, stopped, gone), as it
happens.

## The CLI as an interface

A new harness integration needs four commands and no library:

```sh
boxer hook <harness>    # reads the harness's hook JSON on stdin, writes its dialect back
boxer mcp               # boxer_run and boxer_status over stdio
boxer brief --json      # the mount, mode, intercept list and tasks, for a prompt
boxer run -c '<line>'   # the escape hatch: a shell line in the guest
```

`boxer hook` speaks nine dialects. If your harness resembles one, add a row rather than writing a
bridge; see
[Adding a harness](https://github.com/BarakChamo/boxer/blob/main/docs/adding-a-harness.md).
Otherwise, `boxer run` is a stdio pipe that returns the guest's exit code.

## Worth knowing before you build

**Provisioning is idempotent.** `Ensure` and `boxer up` do nothing on a running sandbox, so call
them freely rather than tracking state.

**boxer strips its own shim directories from `PATH`** before starting anything, so boxer never
resolves its own shim. If your tool manipulates `PATH` around boxer, do not undo this: a `uname`
shim would call `boxer run -- uname` inside a boxer already working on the same sandbox, and the
session deadlocks.

**A sandbox costs about 700 MB of disk** and around a gigabyte resident, against a default 4 GB
allocation. A tool that opens one per task should decide when to close them. `boxer gc` and
`auto_reclaim` reclaim automatically; `boxer down --scope NAME` removes one.

**Use `auto:` ports in anything you generate.** A fixed host port collides as soon as a second
worktree starts.
