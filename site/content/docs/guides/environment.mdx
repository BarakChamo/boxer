title: Set up the guest environment
description: Choose an image, install dependencies with image_setup, setup or prep, run services, forward ports, and set environment and network.
---

Everything a sandbox has is set in `boxer.toml`. This page covers each key in the order boxer uses
it; [the configuration reference](/docs/reference/configuration) lists every key and its default.

```toml
image       = "mirror.gcr.io/library/node:24-alpine"
image_setup = ["apk add --no-cache git"]
setup       = ["npm ci"]
start       = ["npx next dev -p 3000 -H 0.0.0.0"]
ready       = "node -e \"fetch('http://127.0.0.1:3000/').then(r=>process.exit(r.ok?0:1),()=>process.exit(1))\""

[network]
allow_hosts = ["registry.npmjs.org"]
ports       = ["auto:3000"]
```

## Choose an image

```toml
image = "node:24-bookworm-slim"
```

Any OCI reference works. Without one, boxer picks an image from the worktree's lockfile:
`package-lock.json`, `pnpm-lock.yaml` and `yarn.lock` get `node:24-bookworm-slim`, `uv.lock`,
`requirements.txt` and `pyproject.toml` get `python:3.12-slim-bookworm`, `bun.lock` gets
`oven/bun:1-slim`, `Cargo.lock` gets `rust:1-slim-bookworm`, and `go.mod` gets `golang:1-alpine`.
With none of them, boxer uses `debian:bookworm-slim`.

A microVM starts by attaching the image's filesystem, so image size is start-up time on every
`boxer up`. Measured on an M4 with the pack already built:

| image | `boxer up` | first pack build |
| --- | ---: | ---: |
| `alpine:3.21` | 0.6s | 8.6s |
| `node:24-alpine` | 1.7s | 10.9s |
| `node:24-bookworm-slim` | 2.5s | 13.4s |
| `node:24-bookworm` | 9.5s | 26.2s |

Alpine uses musl rather than glibc, so a dependency that ships only a glibc prebuilt fails there.
A slim image has no compiler. If a dependency builds from source, install the toolchain in
`image_setup` instead of switching to the full image.

A local image works too. Nothing is pulled for one, so no registry host has to be allowed:

```toml
image = "./dev.tar"        # a docker save archive
image = "./rootfs"         # an extracted rootfs directory
image = "-"                # read from stdin
```

<Callout>
Docker Hub allows 100 anonymous pulls an hour, which several sandboxes can use up. Pull public
images through `mirror.gcr.io/library/`, which has no quota.
</Callout>

## Install dependencies

Three keys install things. They differ in where they run and what they write to:

| key | runs | how often | use it for |
| --- | --- | --- | --- |
| `image_setup` | in the guest, as root | once per sandbox; on smolvm, once per host, because the result goes into the [environment pack](/docs/concepts/scopes-and-packs#packs) | system packages, global tools, compilers |
| `setup` | in the guest, in the mounted worktree | once per worktree, and again after the list changes | `npm ci`, `uv sync`, anything that writes into the worktree |
| `[prep] commands` | on the host, in the worktree | once per worktree, and again after the list changes | installing packages that ship prebuilt binaries, faster than the guest can |

```toml
image_setup = ["npm i -g typescript"]   # changes the guest image
setup       = ["npm ci"]                # writes node_modules into this worktree
```

Do not put `npm ci` in `image_setup`. The pack records it as done, but `node_modules` lives in the
worktree, which the pack does not carry, so the next worktree starts with no dependencies.

`boxer up --rebuild` recreates the sandbox, drops its pack if it has one, and with it the `setup`
record, so both run again. Use it when something outside these keys changed, such as a base image
tag that moved.

### Host package caches

boxer mounts the host's package cache into the guest read-only, chosen by lockfile: `~/.npm` for
`package-lock.json`, and the pnpm, yarn, bun, uv, poetry, cargo and Go caches for theirs. The
install still runs in the guest, so native binaries are still built for the guest.

```toml
[cache]
enabled  = true          # the default
managers = ["auto"]      # or a list: npm, pnpm, yarn, bun, uv, poetry, cargo, go
```

### Install on the host with prep

`[prep]` runs on the host while the sandbox boots, and boxer waits for it before `setup` starts. It
is devcontainer's `initializeCommand`. `$BOXER_TARGET_FLAGS` carries the guest's platform, so npm,
pnpm and bun fetch the Linux binaries:

```toml
[prep]
commands = ["npm ci $BOXER_TARGET_FLAGS"]   # --os=linux --cpu=arm64 --libc=musl on alpine, Apple Silicon
target   = "auto"                           # the default; or "none", or "linux/arm64/musl"
```

A package that compiles at install time (`better-sqlite3`, `node-pty`) builds for the host whatever
the flags say, and fails in the guest with `invalid ELF header`. `boxer up` and `boxer doctor` warn
when `package-lock.json` has one of the common ones; the list is not complete. Install those
projects with `setup`. [`examples/host-prep`](/docs/guides/examples) is a working config.

### From a devcontainer

If the repository has `.devcontainer/devcontainer.json`, boxer reads it first:
`onCreateCommand` becomes `image_setup`, `postCreateCommand` becomes `setup`, `postStartCommand`
becomes `start`, and `initializeCommand` becomes `[prep]`. It also reads the image, ports,
environment, bind mounts and `remoteUser`, and names anything it will not do, such as `features`
or `runArgs`. Any key in `boxer.toml` overrides it. The full mapping is in the
[configuration reference](/docs/reference/configuration#devcontainerjson).

You still need a short `boxer.toml` for the allowlist, because devcontainer has no key for it and
boxer's default network reaches only the image registry.

## Run services

`start` launches long-running processes; `ready` is a command boxer polls until it exits 0.

```toml
start = ["npm run dev"]
ready = "curl -sf http://127.0.0.1:3000/ >/dev/null"
ready_timeout = "120s"     # the default is 60s
```

Each `start` line runs detached in the worktree, after `setup`, every time the sandbox starts. A
process that exits is not restarted. When `ready` does not pass in time, boxer quotes the tail of
`/tmp/boxer-start.log`, where the services' output goes.

## Forward ports

```toml
[network]
ports = ["auto:3000"]
```

`auto:3000` takes a free host port and forwards it to 3000 in the guest. `"8080:3000"` fixes the
host port, which fails as soon as a second worktree starts, so use `auto:` in anything you commit.
Forwards bind `127.0.0.1` on the host. Ports are fixed when the sandbox is created, so after
changing the list run `boxer up --recreate`.

<Callout type="warn">
The server must listen on `0.0.0.0` in the guest. A forward arrives on the guest's network
interface, so a server bound to `127.0.0.1` never sees it, and a `ready` probe in the guest does not
catch this.
</Callout>

```toml
start = ["npx next dev -H 0.0.0.0"]       # next
start = ["npx vite --host 0.0.0.0"]       # vite
```

`boxer status` prints where each guest port landed:

```console
$ boxer status
boxer: swift-crab (sb-7e1852e4a3c3) running, image node:24-bookworm-slim, mounted /Users/me/src/myapp -> /workspace
  port:      guest 3000 -> http://127.0.0.1:61234
```

A dev server reached through a forwarded port sees an origin it does not expect. Next.js 15 warns
about every dev chunk and says a future version will refuse them; add
`allowedDevOrigins: ["127.0.0.1", "localhost", "*.localhost"]` to `next.config.ts`.

To give each worktree's server a name instead of a port number, turn on
[`[urls]`](/docs/guides/urls).

## Set environment variables and secrets

```toml
[env]
NODE_ENV = "development"          # stored in the pack

env_passthrough = ["CI"]          # copied from the host on each run; the default
secrets = ["NPM_TOKEN"]           # the same, and kept out of argv
```

`[env]` is part of the pack key, so put nothing secret there. `env_passthrough` and `secrets` are
read from the host every time. [Security](/docs/concepts/security#secrets) says how secrets travel.

## Add mounts and choose the user

```toml
mounts = ["~/datasets:/data:ro"]   # host:guest, or host:guest:ro
user   = "node"                    # a name or uid[:gid]; the default is the image's USER
```

The worktree is always mounted at `mount_at` (`/workspace`). `user` runs `setup`, `start` and every
command; `image_setup` always runs as root.

## Control the network

```toml
[network]
mode = "allowlist"
allow_hosts = ["registry.npmjs.org"]
```

`allowlist` (the default) allows the image registry and the hosts you name, `on` allows everything,
and `off` allows nothing. Only smolvm enforces an allowlist. docker, podman and Apple `container`
refuse `allowlist`, so set `on` or `off` there; see [Backends](/docs/concepts/backends). When an
install fails on a missing host, boxer's error names it.
