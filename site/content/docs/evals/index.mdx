---
title: Evaluations
description: The evaluation tiers that check boxer's claims against real agents and runtimes, and what each costs.
---

The evaluation tiers run real coding agents against real runtimes to check what unit tests cannot:
that a harness's commands run in the sandbox, that an integration level holds, that each worktree
gets its own sandbox, and that an agent finds its own dev server. Every result is published with
the conditions it was measured under.

| Tier | What it asks | Cost |
| --- | --- | --- |
| smoke | Does every configuration path work on each backend? | free, minutes |
| `t1` | Does each integration work, with a scripted model? | free, fast |
| `t2` | The same, with real models | cents |
| `adherence` | When boxer only *asks*, how often do agents comply? | cents |
| `flow` | Can an agent develop against a dev server in the sandbox? | ~$0.20 |
| `sdlc` | Twelve development lifecycles in parallel worktrees | ~$0.30 |
| `matrix` | The same workload at every integration level | $2 to $3 |

An integration level is how boxer routes a harness's commands into the sandbox: a hook rewrite, a
PATH shim, or running the harness inside the guest. [Enforcement](/docs/guides/enforcement) lists
them.

```sh
make smoke          # one backend; BOXER_BACKEND=docker make smoke for another
make eval-t1        # no credentials needed
make eval-matrix    # needs AI_GATEWAY_API_KEY
```
